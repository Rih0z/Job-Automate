# /review-business-idea — ビジネスアイデア 品質レビュー（エージェント分離実行）

> **このスキルは別エージェントを起動してレビューを行う。現在のセッションでは直接レビューしない。**
> アイデア作成時の思考過程・設計判断・会話履歴をレビューエージェントに渡さないことで客観性を確保する。

対象: `business-idea` skill をもとに発展・整理されたビジネスアイデア文書
目的: 「独自性・競合克服戦略」「市場性・成長性」「実現可能性」「ペルソナ明確性」「エンゲージメント・リテンション設計」「展開計画の具体性」の6軸で100点満点評価する。

---

## 前提条件（この repo 固有の依存と代替）

- `.claude/skills/_shared/review-rubrics.yaml`: 行動原則と S/A/B/C/D 判定帯の参照元（この repo 固有）。ステップ1の前に存在を確認する。無い環境では判定ラベルを付けず、総合点と観点別得点のみを報告させる（帯を推測で補わない）。
- `.claude/agents/readonly-reviewer.md`: 書き込み系ツールを持たないレビュー用 agent（この repo 固有）。無ければ ステップ2 の通り "general-purpose" で代替する。
- `workflows/business-planning/review-business-idea.md`: 元プロンプト（詳細確認用、任意）。無くても本 skill と references/ だけでレビューは完結する。
- 他 repo へ移すときは references/ ごとコピーする。

## 実行手順

### ステップ1: 情報収集（この実装セッションで行う）

以下の事実情報のみを収集する。作成の意図・設計判断の説明は**含めない**。

```
収集対象:
1. レビュー対象のビジネスアイデア文書の全文
2. 以下の「レビュー前の必須確認事項」が文書内または作成者からの回答で判明しているか
   - このビジネスアイデアで解決したい課題は何か（1〜2文で言語化できるか）
   - 誰のために・誰が使うビジネスか（ターゲット顧客・ペルソナの明示有無）
   - このアイデアをどの段階まで発展させたいか（検討段階・投資検討・実行フェーズ）
   - `business-idea` skill のどのステップまで使ったか
```

上記が不明瞭な場合は、レビュー開始前に作成者へ確認すること。対象ファイルが読めない・存在しない場合は、パスをユーザーに再確認し、確認できるまで次へ進まない。

使用例:

```
ユーザー: 「docs/ideas/pet-app.md をレビューして」
→ ステップ1で文書全文と必須確認事項を収集（ターゲット不明なら作成者に質問）
→ ステップ2でレビューエージェントを起動
→ ステップ3で総合点・S/A/B/C/D 判定・観点別採点表をそのまま表示
```

エッジケース: 文書が下書きで 6 軸の一部（例: 展開計画）が丸ごと欠けている場合も除外せず、レビュー結果で該当軸を低得点として指摘させる。

### ステップ2: レビューエージェント起動

**Agent ツール**を使い、以下の設定で別エージェントを起動する。Agent の起動に失敗した場合は、エラー内容をユーザーに伝えたうえで subagent_type を "general-purpose" に変えて 1 回だけ再試行する。それでも起動できなければ、実装セッション内で代行レビューせずに中断して報告する:

```
Agent ツールの設定:
- subagent_type: "readonly-reviewer"（`.claude/agents/readonly-reviewer.md`。書き込み系ツールを持たない。定義が無い環境・新設直後で未読込のセッションでは "general-purpose" で起動し、prompt 冒頭に「ファイルを作成・変更・削除しない」と明記する）
- description: "Review business idea objectively"
- prompt: 以下のテンプレートに収集した情報を埋め込む
```

**プロンプトテンプレート**（レビューエージェントに渡す内容）: [references/review-prompt-template.md](references/review-prompt-template.md) の「テンプレート本体」を Read し、`[ここに...]` を収集した情報で置き換えて prompt に使う。テンプレートには次の内容が含まれる。

| 含まれる内容 | 概要 |
|---|---|
| 行動原則 | `.claude/skills/_shared/review-rubrics.yaml` の共通原則（evidence_based / citation_required / non_destructive）を Read して適用 |
| 6軸ルーブリック | 独自性・競合克服戦略(20) / 市場性・成長性(15) / 実現可能性(15) / ペルソナ明確性(15) / エンゲージメント・リテンション設計(20) / 展開計画の具体性(15)。各軸にチェック項目と採点目安の表 |
| 採点方法 | 同 yaml の `verdict_scales.rank5_100` で S/A/B/C/D を判定 |
| 出力フォーマット | 基本情報 / 総合評価 / 観点別採点表 / 良かった点 / 改善提案 / 強化が必要な箇所 / 重要チェック項目 / 次のアクション / 補足コメント |

### ステップ3: 結果の報告

レビューエージェントから返却された結果を、そのままユーザーに表示する。
要約や解釈を加えない（レビューの客観性を維持するため）。

---

## 注意事項

- **絶対に実装セッション内で直接レビューしない**。必ず Agent ツールで別エージェントを起動すること
- レビュワーは元ファイルを絶対に編集してはならない。改善点は具体的に指摘し、修正案は「提案」として記載する
- 上記「レビュー前の必須確認事項」が文書から読み取れない場合は、作成者へ確認する
- 判定の根拠には、対象文書の該当箇所（見出し名または行番号）を引用させる。引用できない減点は行わせない
