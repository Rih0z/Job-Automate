# サムネイル画像レビュー

**重要**: 根拠の無い項目と「照合不可」の項目は、クリアとして数えない(合格扱いにしない)。判定は画像と参照資料を目で突き合わせた結果だけで決める。

このスキルは本文だけで判定が完結する（原本が無い環境でも動く）。補足として原本 `workflows/content-creation/review-thumbnail.md`（リポジトリルートからの相対パス）があれば参照してよいが、本文と食い違う場合は本文の判定基準と判定ルールに従う。

## 入力と前提

- 入力: レビュー対象のサムネイル画像ファイルの絶対パス（PNG/JPEG）。Read ツールで画像を開いて目視する（画像を表示できる Read ツールが前提。画像を読めない環境では実行しない）。パスが無い、または画像が読めない場合は実行せず、パスの再提示をユーザーに求める。
- 比較用に、土台の実写真・ブランド要素(マスコット/ロゴ)の単体参照画像があれば、同様に Read で開いて視覚照合する。無い場合、その照合項目は「照合不可」と明記して評価対象から外す（合格扱いにしない）。
- 照合用に、サムネイルを使う記事の現行のタイトルと本文（または要点）があれば Read で開く。無い場合、下の「記事との不一致」の項目は「照合不可」と明記して評価対象から外す（合格扱いにしない）。画像に焼き込んだ文字は記事本文の文字列検索に出ず、記事を直しても画像の文字だけが古いまま残りやすい。
- 原本ファイルが読めない・無い場合は、下の項目だけで評価し、その旨を結果に書く。
- 他リポジトリにコピーする場合は、原本と `thumbnail-generation` の手順書も一緒に移す。

## 手順

1. 原本があれば Read する（任意。無ければ飛ばす）。
2. 画像を Read で開く。
3. 次の項目を 1 つずつ、省略せずに突き合わせる。各項目に「クリア / 該当 / 照合不可」と、画像上の根拠(位置・見えた文字など)を 1 文付ける。
   - **A. 整合性(CRITICAL)**: 各項目は違反の形で書いてあり、画像に当てはまれば「該当」とする。ブランド要素の数・構成の誤り / 参照画像との輪郭・配色の不一致 / 表情・ポーズの単調さ(ブランド要素が同じ表情・同じポーズで並ぶ) / 実写真の質感の喪失(イラスト化・描き替え) / 実在の看板・銘板などの文字が元写真と不一致 / 固有名詞の表記誤り / 文字のはみ出し、または最重要語が最も目立つ文字になっていない / 括弧・引用符の対応の崩れ / 架空要素(元写真に無い図案)の描き足し / ブランド要素の暴走(別人物化・見出しブロックの増殖・土台の大部分の遮蔽・別キャラへの置換) / 記事との不一致(画像の題、副題、数値、用語が、記事の現行のタイトルと本文の記述と違う。本文で直した語や数値が画像に古いまま残っている)
   - **B. CTR 観点(全 5 項目)**: B1 視覚要素が 3 つ以内 / B2 見ただけで何が分かるかが伝わる(フックが読める) / B3 感情の強い表現 / B4 見出し文字が 0〜3 語程度 / B5 縮小表示でも判読できる
   - **C. 補助確認(Read のみで実施)**: スクリプトは実行しない(allowed-tools は Read のみ)。画像の四辺付近で文字が切れていないか、小さい文字が潰れていないかを、Read で開いた画像上で再確認する。縮小表示の判読性は「長辺が約 300px になった状態を想像して読めるか」で判断し、確信が持てなければ「照合不可」とする。目視の代替としての自動判定はしない。

## 判定

ラウンドは `thumbnail-generation` の生成段階を指す(Round 1 = 土台生成、Round 2 = 創造的仕上げ、Round 3 = CTR フック追加と修正)。

- A に 1 項目でも該当 → **REGENERATE**(該当ラウンドから再生成。多くは Round 1 から)
- A 全クリア かつ B(5 項目中)4 項目以上クリア → **PASS**
- A に「該当」が無く「照合不可」だけがある場合: 照合できた項目だけで上の判定を行い、判定の後ろに「(照合不可: 項目名)」を付ける。照合不可の項目はクリアとして書かず、照合に要る資料(参照画像、記事)を次のアクションに書く。どの資料が無いとどの項目が照合不可になるかは次の表のとおり
- A 全クリア だが B が 3 項目以下 → **REVISE**(コンテンツフック追加ラウンドで改善)

| 無い資料 | 照合不可になる A の項目 |
|---|---|
| 土台の実写真 | 実写真の質感の喪失 / 実在の看板・銘板などの文字が元写真と不一致 / 架空要素の描き足し |
| ブランド要素の単体参照画像 | 参照画像との輪郭・配色の不一致 |
| 記事の現行のタイトルと本文 | 記事との不一致 |

## 出力形式

```markdown
# サムネイルレビュー結果
- 対象: (画像パス)
- 判定: PASS / REVISE / REGENERATE(照合不可があれば「(照合不可: 項目名, …)」を続ける)
## A. 整合性
| 項目 | 結果(クリア/該当/照合不可) | 根拠 |
## B. CTR(クリア数 N/5)
| 項目 | 結果 | 根拠 |
## C. 補助確認(Read のみで実施)
## 次のアクション(REVISE/REGENERATE の場合、戻るラウンドと修正点。照合不可がある場合、照合に要る資料)
```

この形式の節だけを出力し、生成の感想や画像の説明文は足さない。

## エラー時の対処

| 状況 | 対処 |
|------|------|
| 画像が読めない・存在しない | 実行せず、正しい絶対パスをユーザーに求める |
| 画像形式が PNG/JPEG 以外(GIF・WebP・動画など) | 判定せず、PNG/JPEG への変換版を求めて止める |
| 参照画像(土台写真・ブランド要素)が無い | 該当の照合項目を「照合不可」とし、合格扱いにしない |
| 記事のタイトルや本文が無い | 「記事との不一致」を「照合不可」とし、合格扱いにしない |
| 項目の判定が境界で迷う(A の「該当」か微妙など) | A は迷ったら「該当」寄りで REGENERATE 側に倒し、根拠に迷った旨を書く。B は迷ったら「クリア」にせず、根拠不足と明記する |
| 結果の出力が上記形式から崩れた | 形式に沿って 1 回だけ書き直す |

## 制約

- 自己レビュー(作成した本人の印象)ではなく、チェックリストの突き合わせで判定する。
- 画像の編集・再生成・ファイルの書き換えはしない(allowed-tools は Read のみ)。根拠のない項目は「クリア」にしない。

## 使用例

- 「`thumb/final.png` をサムネイルレビューして」 → 画像を Read → A の 11 項目に「看板の文字が元写真と違う」が該当 → REGENERATE(Round 1 から新規セッションで)と報告。
- thumbnail-generation 以外で作った画像で、土台写真もブランド要素の参照画像も無い → 判定の節の表のとおり 4 項目を「照合不可」とし、残りの項目で判定して「PASS(照合不可: 参照画像との輪郭・配色の不一致, 実写真の質感の喪失, 実在の看板・銘板などの文字が元写真と不一致, 架空要素の描き足し)」のように判定に添える。記事も無ければ「記事との不一致」も加える。
- A は全クリアだが、B で「見出し文字が 5 語ある」「縮小すると読めない」「視覚要素が 4 つ」「表情が弱い」の 4 件が該当し、B のクリアが 1/5 → REVISE と報告し、次のアクションに「見出しを 3 語以内に」「文字を大きく」を書く。

対象の生成手順は `thumbnail-generation` skill (`workflows/content-creation/thumbnail-generation.md`)。
