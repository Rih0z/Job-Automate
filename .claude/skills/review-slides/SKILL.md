# make-slide.md スライド 品質レビュープロンプト（エージェント分離実行）

> **このスキルは別エージェントを起動してレビューを行う。現在のセッションでは直接レビューしない。**
> 実装コンテキスト（生成過程・設計判断・会話履歴）をレビューエージェントに渡さないことで客観性を確保する。

対象: $ARGUMENTS

原本（Job-Automate repo 内の場合のみ）: `workflows/content-creation/review-slides.md`（リポジトリルートからの相対パス）。原本が無い環境でも、5軸の詳細基準は `references/review-criteria.md` に取り込み済みなので動作する。
対応する作成プロンプトは `slides-pro` skill（Job-Automate repo 内）。他環境では、作成側の規約（`make-slide.md` 相当）が渡されていなければ、その規約への準拠度は「規約未参照」と明記して採点する。

前提: このスキルは手動起動専用（`disable-model-invocation: true`）で、description のトリガーフレーズは `/review-slides` を使うべき場面の目安。`.claude/agents/readonly-reviewer.md` と `.claude/skills/_shared/review-rubrics.yaml` は Job-Automate repo の固有ファイルで、あればそれを使う。無い環境では `references/reviewer-fallback.md`（審査エージェントの条件・共通原則・S/A/B/C/D 判定帯・重大指摘の扱い）で代替でき、SKILL.md と references/ だけで動く。`$ARGUMENTS` が空、またはパスのファイルが存在しない場合は、レビューを開始せず対象 HTML の絶対パスをユーザーに尋ねる。

使用例:

1. 「`out/deck.html` のスライドをレビューして」 → `$ARGUMENTS` に絶対パスを置いて実行 → ステップ1で HTML 全文・枚数・聴衆情報を収集 → ステップ2で readonly-reviewer を起動 → 5軸の採点表と S/A/B/C/D 判定をそのまま表示。聴衆が不明でも「不明」と明記して続行する。
2. 「この .pptx をレビューして」 → 対象は HTML スライド専用なので実行しない。.pptx は対象外である旨を伝え、HTML 形式のスライドの絶対パスを求める。
3. レビュー結果に総合点や判定が無く、観点別採点表も欠けていた場合 → フォーマット遵守を明記して 1 回だけ再起動する。なお崩れる場合は、崩れている旨を添えてそのまま表示する（詳細は「エラー時の対処」）。

## 実行手順

### ステップ1: 情報収集（この実装セッションで行う）

以下の事実情報のみを収集する。作成意図・目的・設計判断の説明は**含めない**。

```
収集対象:
1. レビュー対象 HTML スライドファイルの内容全文
2. スライド総枚数
3. 適用した make-slide.md のバージョン・特記事項（HTMLコメント等から検出できれば）
4. 想定聴衆・プレゼンの目的・ゴール（作成者から確認できれば。不明な場合はその旨を明記して収集を続行）
```

### ステップ2: レビューエージェント起動

**Agent ツール**を使い、以下の設定で別エージェントを起動する:

```
Agent ツールの設定:
- subagent_type: "readonly-reviewer"（`.claude/agents/readonly-reviewer.md`。書き込み系ツールを持たない。定義が無い環境・新設直後で未読込のセッションでは "general-purpose" で起動し、prompt 冒頭に「ファイルを作成・変更・削除しない」と明記する）
- description: "Review HTML slides objectively"
- prompt: 以下のテンプレートの「## 収集情報」欄に、ステップ1で収集した内容（HTML 全文・総枚数・バージョン特記事項・想定聴衆）を貼り付け、末尾の $ARGUMENTS を対象パスに置き換える
```

**プロンプトテンプレート（レビューエージェントに渡す内容）:**

````
あなたは作成者とは別の客観的なプレゼンテーションレビュアーです。
以下の HTML/CSS プレゼンテーションスライドを、5軸・各20点・計100点満点で評価してください。
レビュワーは元ファイルを絶対に編集してはならない。フィードバックの提供のみ行う。

## レビュー前の確認事項

以下が不明な場合は、レビュー結果の「基本情報」欄に「不明」と明記した上でレビューを続行すること。
- このプレゼンで最も伝えたいこと
- 想定聴衆（技術者・非技術者・経営層など）
- 聴衆がこのスライドを見た後に何を「できる」「わかる」ようになるか
- 適用した make-slide.md のバージョン・特殊な省略/変更

## レビュー観点（5項目・各20点）

詳細なチェック項目と採点目安は `.claude/skills/review-slides/references/review-criteria.md` にある（skill の配置先が違う場合は、この skill の `references/` を指す）。これを Read し、全項目を省略せずに適用すること。読めない場合はその旨を結果の「補足コメント」に書き、5軸の名称（1. 技術準拠・HTML/CSS品質 / 2. 視認性・コントラスト / 3. 情報量・レイアウト適切性 / 4. コンテンツ構成・論理性 / 5. プレゼン効果・伝達力）と各20点の配点だけで採点して「詳細基準未参照」と明記する。

## 採点方法

総合点：100点満点。`.claude/skills/_shared/review-rubrics.yaml` を Read し、`verdict_scales.rank5_100` の bands/meaning に従って S/A/B/C/D を判定すること（点数帯・各段階の対応方針は同ファイルが SoT）。同ファイルが無い場合は `references/reviewer-fallback.md` の判定帯と共通原則を適用する。行動原則（証拠主義・引用義務・非破壊）は同ファイルの `common_principles` を適用する。
````

### エラー時の対処

| 状況 | 対処 |
|------|------|
| 対象 HTML が読めない・存在しない | 実行せず、正しい絶対パスをユーザーに求める |
| `_shared/review-rubrics.yaml` が読めない | レビューエージェントに読めなかった旨を伝え、テンプレート内の採点目安のみで採点させる。判定には「rubrics 未参照」と明記 |
| Agent の起動に失敗した | `readonly-reviewer` が無ければ `general-purpose` で再試行。それでも失敗なら未実施と報告し、現セッションで代替レビューはしない |
| 返却結果が出力フォーマットに沿わない | フォーマット遵守を明記して 1 回だけ再起動。なお崩れる場合はそのまま表示し、崩れている旨を添える |

### ステップ3: 結果の報告

レビューエージェントから返却された結果を、そのままユーザーに表示する。要約や解釈を加えない（レビューの客観性を維持するため）。

## 注意事項

- **絶対に実装セッション内で直接レビューしない**。必ず Agent ツールで別エージェントを起動すること
- レビューエージェントに渡す情報は事実（スライドHTML内容・スライド枚数等）のみ。作成の意図・設計判断は渡さない
- レビュワーは元ファイルを絶対に編集してはならない（フィードバックの提供のみ）
