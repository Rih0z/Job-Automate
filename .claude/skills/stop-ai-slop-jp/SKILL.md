# Stop AI Slop(日本語版)

AIで書いた日本語を、そのまま外に出せる文章に戻す。

## 大原則

AI臭の正体は、書き手の不在だ。自分が何を見て、何に引っかかって、どこまで言い切るのか。そのコアをAIに預けると臭う。全角ダッシュや偏愛語は、表面に出てくる症状でしかない。

書く前と書いた後に、自分に問う:

- 自分は何を「○○だ」と引き受けているか
- 誰かが反論できる具体的な主張があるか(「いや、Bだろう」と言える内容か)
- 同じテーマの平均的な記事と、どこで違うか

ここに答えられないなら、表面修正は後回しでいい。先に「自分は何が言いたいのか」を決める。

## コアルール

### A. 主体と立場(最優先)

1. **false agencyを潰す**。モノに人間の動詞をさせない。「データが示している」「文化が醸成される」「お弁当が設計されていた」を、誰が何をしたかに書き換える。詳しくは `references/structures.md`。
2. **反証可能な主張を持つ**。「重要だ」「本質的だ」で終わらせず、誰かが反論できる具体に降りる。降りられないなら、その文を削る。
3. **強度を一段下げ、中間温度を混ぜる**。全部を「すぎる」「最高」「ヤバい」にしない。「悪くない」「まあまあ」「微妙」「よく分からん」を入れる。本当に強い感情のときだけ強い言葉を使う。
4. **断定を押し付けず、伝聞を残す**。調べた事実には「らしい」「そうです」「ようだ」「と聞いた」を混ぜる。Wikipedia/辞書のような断定型は避ける。
5. **遠くから語らない**。「人々は〜する傾向にある」「多くのエンジニアが」「現代社会において」をやめ、「自分は」「あなたは」で書く。一般論だけが続くなら、具体的な人・失敗・数値・固有名詞を入れる。
6. **両論併記を捨て、毒を許す**。「○○もあり、△△もあります」のような全方位肯定は判断の放棄。「自分はこれを選んだ」「あれはダメだった」を引き受ける。罵倒・自虐・皮肉は人間の文章の証拠なので、必要な箇所では削らず残す。AIは毒を書けないので、書き手が手で書き足す。

### B. 構造

7. **命題型H2を避ける**。見出しは「テーマの名前」(名詞句)で立てる。「○○は△△だ」型は各節を小さなTED talkにする。
8. **二項対比を直接Yに変える**。「AではなくBだ」「単なるAではなくB」を「Bだ」と直接書く。
9. **ムラを入れる**。段落の長さ、トーン、結論の有無、密度、文末語尾を意図的にバラけさせる。全段落を同じ強度で着地させない。
10. **3項目並列を疑う**。「3つのポイント」「3つの観点」「3つの原則」を、2つか1つに削れないか考える。AIは3つ並べたがる。

### C. 語彙と記号

11. **偏愛語・必殺技造語・副詞を撒かない**。「泥臭さ」「手触り」「解像度」「本質」「営み」「文脈」、および「真理」「虚飾」「禁欲的」「美学」「境地」のような必殺技造語を1記事に複数撒かない。「非常に」「めっちゃ」「普通に」「ガチで」は1段落に2個以上重ねない。禁止リストは `references/phrases.md`。
12. **横文字メタファーを日本語に戻す**。「思考のOSをアップデート」「人生をハック」「習慣をインストール」「マインドをリファクタリング」を、「考え方を変える」「工夫する」「習慣をつける」「考え方を整理する」に戻す。「コンテキスト」「アライメント」「コミュニケーション」のような普通の日本語に戻せるカタカナ語も、戻す。
13. **形容詞や心情に「」を使わない**。固有名詞か直接引用以外で「」を使わない。「軽い」「動けばヨシ」のような普通の語を引用符で囲まない。
14. **記号のアーティファクトを潰す**。全角ダッシュ ── はコロン・改行・読点に置換。中黒並列 A・B・C は「と」「や」で繋ぐ。`**` 残骸、コロン後の半角スペース、装飾絵文字(🚀🎯✨💡)の均等撒布は検索 → 全置換。

### D. 事実整合性（BLOCKER相当、slopとは別レイヤ）

文体の良し悪し（slop採点）ではなく**事実の誤り**であり、スコアに関わらず最優先で是正する。チェック項目は `criteria/scoring.json` の `blocker_checks`（5 項目: 帰属誤り `misattribution`・属性の過小断定 `audience_underassertion`・指示文のメモ書き化 `instruction_echo`・意味の一意性 `single_meaning`・意味の伝達 `conveyance`）を SoT とする。各項目の定義、`conveyance` の 4 つの型、誤検出率の数え方は `references/fact-integrity.md` に書いた。

## 採点範囲(文体のみ。事実の実測はしない)

- 採点するのは文体(5軸)だけ。本文の事実主張（件数、コマンドの結果、ファイルの配置や追跡状態、他文書との一致）は、実行・実測して突合しない。突合は、完了判定を担う別エージェントのレビューが受け持つ。
- `blocker_checks` は文面から読み取れる範囲で確認する。実測が要る食い違いに採点中に気づいたら、点数と合否に入れず、採点結果の末尾「範囲外メモ」に逐語引用付きで書く。
- 呼び出し元は範囲外メモを受け取った同じターンで実物を確かめ、誤りなら直す。事実の確認と修正を先に済ませ、文体の採点は最後に通す。
- 理由と詳しい運用（具体性の軸の扱い、メモの渡し方、再採点の範囲）は `references/fact-integrity.md` を読む。

## 確定の条件

合格点（`criteria/scoring.json` の `pass_rule`）を満たした資料を確定する時は、`criteria/scoring.json` の `confirm_rule` の 3 条件を満たす。

1. `agency`（主体性）と `concreteness`（具体性）が各 10 点（false agency と具体の欠落が 0 件）。
2. `stance`・`rhythm`・`reduction` が各 7 点以上。
3. `single_meaning`（意味の一意性）と `conveyance`（意味の伝達）の指摘が 0 件。全文が 1 通りにだけ読め、非専門の読み手が誰が何をどうしたかを言い直せる状態を、文書の種類を問わず確定の条件にする。

採点者は指摘を、確定条件に影響する指摘と、軽微な指摘（1 点未満の好みの差）に分けて返す。軽微な指摘は逐語引用付きで別記し、確定を妨げない。直すかは呼び出し元が決め、確定条件に影響しない指摘のために再採点を重ねない。同じ文面を直すたびに別の軽微な指摘が出る時は、採点者の指摘が往復していないか（片方を直すと逆向きの指摘が出ていないか）を確かめ、往復していれば両立する書き方を採点者に示させる。

## 採点対象の条件と採点基準が矛盾する時

採点基準と、採点対象のディレクトリや生成物の条件が矛盾することがある。矛盾の型と、見つけた時の手順は `criteria/scoring.json` の `conflict_policy` にある（ここには複写しない）。矛盾に気づいたら、文書の修正と再採点を重ねる前に、矛盾しない設計へ見直す必要があるかを先に判断する。見直す場合は、生成側と採点側のどちらを直すかを根拠付きで決める。

## 分析レポート・調査報告モード(2026-09-01 追加)

対象が調査・分析レポート(根拠の確度が案件ごとに異なる報告書)のときは、以下をslop扱いしない:

- **確度・信頼度を示すヘッジ**(「〜と推測される」「確証度: 中」「別解釈の可能性あり」等)は、根拠なく主張を弱める「伝聞口調」(コアルール4)とは別物であり、削らない。確度表示は読み手が結論の強さを判断するための情報であり、機械的に断定形へ書き換える提案はしない。
- **代替仮説の併記**は、コアルール6の「両論併記による判断放棄」とは区別する。分析結果は「Aの可能性が高いが、Bも棄却できない」のように確度付きで複数仮説を残すことが誠実な報告であり、無理に一つの結論へ絞らせない。
- 上記2点以外(構造・語彙・記号レベルの指摘)は通常のコアルールをそのまま適用する。

## 技術文書モード

対象が技術的な原稿(書籍の章、記事、解説文)のときは、`references/tech-writing.md` の規範を併用する。ブログ・体験記を前提にしたコアルールのうち、次は技術文書では**上書き**される。

上書きされるルールの一覧表は `references/tech-writing.md` の「ブログ前提コアルールの上書き表」にある。技術文書では口語の伝聞・毒・崩した語尾・「あなた」呼びなどを使わない方向に倒れる。

語彙・構造カタログ(`phrases.md` / `structures.md`)は技術文書でも有効。加えて `tech-writing.md` が、整形(一文一改行、脚注、太字/「」の使い分け、ダッシュと中黒の例外規定)、段落と論証の構成、論証の厳密さ、読み手の負荷管理、視点と語り、演出の節度、LLMっぽい表現の禁止(技術文書で出やすい型)、冗長の排除、見出し、読者への誠実さを規定する。

## クイックチェック

書き終わったら、上から順に確認する。何より音読が効く。目で読むと気付かない違和感が、口に出すと一気に出てくる。黙読でも、息が続かない箇所、読点を打ちたい箇所、リズムが揃いすぎている箇所を見る。

### 構造レベル
- [ ] H2見出しが「主張」になっていないか?(命題型H2)
- [ ] 序文が決めつけ→反転構造になっていないか?
- [ ] 全段落の長さが3〜5文に揃っていないか?(ムラの欠如)
- [ ] 全段落が「○○なんだなと感じました」型で終わっていないか?
- [ ] 文末が「です」「ます」「だ」のどれかで一貫しすぎていないか?
- [ ] 体験→引用→抽象化のテンプレが3節以上連続していないか?

### 文・段落レベル
- [ ] モノが主語で人間の動詞をやっていないか?(「課題が浮き彫りになる」「思想が結実する」)
- [ ] 「多くの人」「人々」「我々」で、自分の話を一般化していないか?
- [ ] 具体的な人・エピソード・失敗・数値がないまま一般論だけで進んでいないか?
- [ ] 事実を一文に詰めすぎていないか?(伝聞口調があるか)
- [ ] 二項対比(「Aではなく、Bだ」)を多用していないか?
- [ ] 否定的列挙(「Aでもない、Bでもない、Cだ」)を使っていないか?
- [ ] 劇的な断片化(「シンプル。それだけ。それが本質。」)を使っていないか?

### 記号レベル
- [ ] 全角ダッシュ ── が混入していないか?
- [ ] 形容詞や心情を「」で囲んでいないか?
- [ ] 中黒「・」で3項目並列していないか?
- [ ] アスタリスク `**` の残骸がないか?
- [ ] コロン `:` の後に半角スペースがないか?
- [ ] 装飾絵文字(🚀🎯✨💡)が段落末に等間隔で撒かれていないか?

### 語彙レベル
- [ ] AI偏愛語(泥臭さ、手触り、解像度、熱量、本質、思想、設計、装置、営み、文脈)を複数撒いていないか?
- [ ] 必殺技造語(真理、虚飾、禁欲的、美学、境地、結末)で個人の話を膨らませていないか?
- [ ] 横文字メタファー(思考のOS、ハック、インストール、リファクタリング、ポートフォリオ)を撒いていないか?
- [ ] 過剰なカタカナ(コンテキスト、アライメント、コミュニケーション)を、普通の日本語に戻せないか?
- [ ] 英語固有名詞をフル正式名称で律儀に繰り返していないか?
- [ ] 翻訳調動詞(指している、示している、物語っている、収斂する)を多用していないか?
- [ ] 副詞(「めっちゃ」「ガチで」「普通に」「かなり」)を1段落に2個以上重ねていないか?
- [ ] 「○○すぎる」を1記事に3回以上使っていないか?
- [ ] アカデミック自称(「本稿」「本記事」「筆者」)を地の文で使っていないか?

### 事実整合性(スコア対象外・BLOCKER)
- 5 項目のうち、ここでは先頭 2 項目を挙げる。残り 3 項目（指示文のメモ書き化・意味の一意性・意味の伝達）は下の「強度と立場」節の末尾 3 行にある。
- [ ] 帰属誤り: 方針・決定を、実際の発案者・決定者ではない第三者に帰属させていないか?読み手を勝手な肩書で呼んでいないか?
- [ ] 属性の過小断定: ツール・製品・サービスの対象者を、提供元の位置づけだけから「〜専用」と狭く断定していないか?

### 強度と立場
- [ ] 中間温度(「悪くない」「まあまあ」「微妙」)が出てくるか?
- [ ] 反証可能な具体的主張があるか?
- [ ] 抽象的な評価(「本質的」「構造的」)で終わらず、具体に降りているか?
- [ ] 「ケースバイケース」「場合による」で結論を回避していないか?
- [ ] 全方位肯定(「○○もあり、△△もあります」)で判断を放棄していないか?
- [ ] 毒・自虐・皮肉が必要な箇所で削られすぎていないか?
- [ ] 各節末にリチュアル化したdisclaimerを置いていないか?
- [ ] 指示文のメモ書き化: 依頼者の指示の言い回し(括弧書きのラベル、「〜のタブにある」のような画面の案内、作業中の呼び名)が、読み手向けの語に直されないまま見出し・固定文・本文に出ていないか?
- [ ] 意味の一意性: 主語・述語・目的語が読み取れる文か?「対応する」のように状態と方針の両方に読める語や、「のみ」「〜向け」の限定の脱落で、対象読者が書き手の意図と違う事実に取る文が無いか?(読み方 A・B を挙げられる文だけを直す)
- [ ] 意味の伝達: その文だけを読んだ非専門の読み手が、誰が何をどうしたかを言い直せるか?名詞止めで何も言っていない文、初見で意味を取れる手段のない語、「手元の名簿」のような直訳の語、主語と述語が組み合わない文が無いか?(言い直せない文だけを直す)

## 採点

観点定義(SoT) = このスキルの `criteria/scoring.json`(5軸の質問文・1/5/10点アンカー・合格閾値・BLOCKERチェックを保持、本文へ prose 重複記載しない)。5軸を1〜10で採点し合計35/50を下回ったら書き直す(中間点は両隣アンカーの間で判断)。`blocker_checks`(帰属誤り・属性の過小断定・指示文のメモ書き化・意味の一意性・意味の伝達の 5 項目)はスコア対象外・事実の誤りとしてスコアに関わらず最優先で是正する。

### 採点結果の出力形式

採点者は次の順で返す。余計な総評は足さない。

1. 軸別点数(`agency` / `concreteness` / `stance` / `rhythm` / `reduction` を各 1〜10)と合計(50 点満点)
2. 合否: 合計が `pass_rule` を満たし、`confirm_rule` の 3 条件を満たすなら確定可
3. BLOCKER の指摘(型・逐語引用・直し方の案)。0 件なら「なし」
4. 確定条件に影響する指摘と、軽微な指摘(別記)。それぞれ逐語引用付き
5. 範囲外メモ(実物と照らさないと確かめられない食い違い。無ければ省略)

## 使用例

- ユーザー: 「この記事の下書きを AI 臭くないように直して」 → 大原則の 3 つの問いに答えられるか確認 → 事実整合性を先に確認 → 立場、false agency、構造、語彙、記号の順に直す → クイックチェックを通す。直した箇所と理由を短く返す
- ユーザー: 「この報告書を確定前にレビューして」 → 文体を 5 軸で採点し、BLOCKER と軽微な指摘を分けて返す。事実の実測はしない
- 調査・分析レポートの確度表示(「〜と推測される」)や代替仮説は削らない(分析レポート・調査報告モード)

## 失敗時の対処

- `criteria/scoring.json` が読めない: 採点せず、ファイルの配置を確認するよう報告する(5 軸の内容を記憶から再構成しない)
- 対象が日本語以外、または文章でない(コードや表だけ): 対象外としてその旨を返す
- 修正で文意が変わりそうなとき: 変える前に元の文と案を並べて示し、書き手に確認する

## 修正の優先順位

時間が限られているなら、上から順に対処する。1と2を直さず5だけ直しても、AI臭は残る。事実整合性(帰属誤り・属性の過小断定・指示文のメモ書き化・意味の一意性・意味の伝達)は文体の優先順位とは別軸で、発見次第スコアに関わらず即座に直す。

0. **事実整合性**: 帰属誤り・属性の過小断定・指示文のメモ書き化・意味の一意性・意味の伝達がないか?文体修正より先に確認する。
1. **立場**: 反証可能な主張があるか? なければ「自分は何が言いたいのか」を再考する。両論併記の放棄を含む。
2. **false agency**: モノが主語で人間の動詞をやっていないか? 主体を名指しに書き換える。
3. **構造のテンプレ**: 命題型H2、決めつけ序文、ムラの欠如を直す。
4. **語彙とフレーズ**: 偏愛語、必殺技造語、翻訳調、横文字メタファー、副詞スタッキングを削る。
5. **記号**: ダッシュ、不要な「」、中黒並列、`**` 残骸、装飾絵文字を直す。
