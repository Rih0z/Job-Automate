# 評価軸と採点・判定（review-implementation）

目次: 1. 評価軸（5項目・各20点） / 2. 軸ごとの採点目安 / 3. 総合点の判定

## 1. 評価軸（5項目・各20点 = 100点満点）

### 1. テスト実装品質（20点）
- テストファースト証跡（失敗→成功の流れ）
- カバレッジ（正常系・異常系・境界値）
- テスト品質（フレーキーでないか、ハードコードがないか）
- 失敗シグナルの複数明示（戻り値だけでなく例外種別・エラーメッセージ・ログ・副作用の状態等）
- テストの保存場所・実行経路が一意に定義されているか

### 2. 処理の正確性（20点）
- ビジネスロジックの正確性
- エラーハンドリング
- セキュリティ・データ整合性

### 3. マネタイズ設計整合性（20点）
- 収益モデルとの整合
- 収益に影響するUX
- 分析・計測の実装

### 4. ペルソナ・クライアント適合実装（20点）
- ペルソナ定義との整合
- ペインポイント解消
- 文言・ラベルの適切さ

### 5. UX品質（20点）
- インタラクション品質
- ビジュアル・レイアウト品質
- アクセシビリティ・パフォーマンス

## 2. 軸ごとの採点目安（各軸20点）

| 得点 | 目安 |
|------|------|
| 18〜20 | 観点を全て満たし、根拠（ファイル・行）が揃っている |
| 14〜17 | おおむね満たすが、一部の観点に不足・軽微な問題がある |
| 10〜13 | 基本は実装されているが、観点の欠落や重要な不備がある |
| 0〜9 | 観点をほぼ満たさない、または根拠が確認できない |

### 軸固有の減点基準（目安。減点するときは該当行を引用する）

| 軸 | 重く減点する例 | 軽く減点する例 |
|----|----------------|----------------|
| 1. テスト実装品質 | 主要ロジックにテストが無い／異常系・境界値が無い／失敗しても通るアサーション | 実行経路が複数あり一意でない／ハードコードされた期待値 |
| 2. 処理の正確性 | ビジネスロジックの誤り／入力検証なし・秘密情報の平文保持など安全性の欠陥／例外の握りつぶし | エラーメッセージが不明瞭／ログが不足 |
| 3. マネタイズ設計整合性 | 収益モデルと実装した課金・制限が食い違う／収益に直結する導線が壊れている | 計測イベントが一部欠ける／料金表示の文言が不統一 |
| 4. ペルソナ・クライアント適合実装 | ペルソナのペインポイントに対応する機能が無い／専門用語だらけで想定ユーザーが読めない | ラベルの揺れ／ペルソナ未検出で推定ユーザーを使った点（注記があれば減点しない） |
| 5. UX品質 | 主要操作が完了できない／キーボード操作・代替テキストなど基本のアクセシビリティが無い | 余白・配色の不統一／読み込み中の表示が無い |

この表は目安であり、上の4レンジと矛盾する場合は4レンジを優先する。

## 3. 総合点の判定

| 評価 | 点数 | 判定 |
|------|------|------|
| S | 90〜100 | リリース可 |
| A | 80〜89 | 軽微な修正後にリリース可 |
| B | 70〜79 | 重点項目の修正が必要。再レビュー |
| C | 60〜69 | 大幅な修正が必要 |
| D | 59以下 | 根本的な再設計が必要 |

収益モデルが未検出でマネタイズ軸を N/A とした場合は、残り4軸の合計（80点満点）を 合計点 ÷ 80 × 100（小数点以下四捨五入）で100点換算してから判定する。
