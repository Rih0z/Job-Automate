# AI自動化収益モデル生成プロンプト

以下の条件に合致する、AIで自動化可能な収益化ビジネスモデルを10個提案してください。

## 実行手順

1. 前提条件（下記）をユーザー指定で上書きできるか確認する。指定が無ければ既定値で進め、既定値を使ったことを出力冒頭に1行で明記する。
2. 10案を、各案「各アイデアに含めるべき要素」の 1〜9 を全て埋めて作る。
3. 出力前の検証ゲート: 10案が揃っている / 全案で有料サービスを使っていない / 全案で bash（curl・jq・wrangler 等）だけで運用できる / 無料枠の数値に確認日または「要確認」の注記がある。1つでも欠けたら該当案を直してから出力する。
4. 最後に「出力形式」の比較表と推奨3案を付ける。

## 出力形式

- 各案は見出し `### 案N: <名称>` の下に、要素 1〜9 を同じ順序・同じ見出しで書く。
- 末尾に比較表を1つ付ける: 列は 案名 / 実現可能性 / 収益性 / 自動化 / エンゲージメント / 保守性 / 競合優位性 / 加重合計（評価基準の配点で 100 点満点）。
- 比較表の下に推奨3案と理由を各1行で書く。装飾的な前置き・まとめは書かない。

## 例（1案分の書き方。数値は書式の見本で、実案では根拠のある値に置き換える）

```
### 案1: 地域イベント情報の週次ダイジェスト配信
1. 概要: 公開RSSを収集し、Gemini 無料枠で要約して週1で自動配信
2. 自動化の仕組み: Cron Triggers で収集 → curl/jq で整形 → 要約 → Pages へ公開
3. エンゲージメント: 週次の配信日を固定し、過去号アーカイブで継続閲覧を促す。継続率の目標は ○%
4. 技術スタック: Gemini API（無料枠）、Workers、Pages、curl、jq、wrangler
5. 収益化: アフィリエイト、スポンサー枠
6. 差別化: 地域特化の整理済みデータが蓄積される。大手の汎用ニュースが拾わない粒度を狙う
7. 実装難易度と期間: MVP ○週間 / 収益化開始 ○週間 / 月10万円 ○ヶ月 / 完全自動化 ○ヶ月
8. リスクと対策: 取得元の規約変更 → 取得元を複数化し、失敗時は Discord webhook で通知
9. スケーラビリティ: 現在の自動化率 ○% → 対象地域を増やして 100% へ
```

## 前提条件：
- 利用可能ツール：Google Gemini API（無料枠）、Hugging Face API（無料枠）、GitHub Actions、Cloudflare（Workers、Pages、R2、D1、KV）、オープンソースLLM
- 技術スキル：Web開発、インフラ、Azure（上級者レベル）
- 作業時間：週10時間（初期構築後は週2-3時間のメンテナンス想定）
- 目標：2ヶ月で月収10万円の安定収入
- 初期投資：完全0円（無料APIとツールのみ使用）
- **運用方針：bashコマンドによる制作・管理・運営、将来的な全自動化**

## 各アイデアに含めるべき要素：

### 1. ビジネスモデル名と概要（1-2行）

### 2. 自動化の仕組み
- データ収集/生成方法
- コンテンツ作成プロセス
- 配信/公開の自動化
- 収益化の自動化

### 3. エンゲージメント・リテンション設計
- ユーザーが継続利用する仕組み（習慣ループ・通知・進捗可視化等）
- 報酬設計（達成感・社会的承認・金銭的リターン等の変動報酬）
- ネットワーク効果（ユーザー増加に伴う価値向上の仕組み）
- スイッチングコスト（データ蓄積・カスタマイズ・コミュニティ等による離脱障壁）
- リテンション指標の目標（DAU/MAU・継続率・チャーン率）

### 4. 必要な技術スタック
- 使用するAPI（完全無料枠のみ）
- Cloudflareサービスの活用方法
- 必要なプログラミング言語
- CLIツール（curl、jq、wrangler等）

### 5. 収益化方法（複数可）
- アフィリエイト
- 広告収入
- サブスクリプション
- デジタル商品販売
- その他

### 6. 差別化ポイント
- 競合が参入しにくい理由
- ユニークな価値提案
- 競合の強みに対するカウンター戦略
- 競争優位の持続性（モート：データ蓄積・ネットワーク効果・ブランド等）

### 7. 実装難易度と期間
- MVP完成まで：○週間
- 収益化開始まで：○週間
- 月10万円達成見込み：○ヶ月
- 完全自動化達成：○ヶ月

### 8. リスクと対策
- 主なリスク要因
- リスク軽減策
- 自動化によるエラー検知と対処

### 9. スケーラビリティと自動化レベル
- 将来的な拡張可能性
- 現在の自動化率：○%
- 最終的な自動化率：100%への道筋

## 無料で使えるAIサービス（無料枠の数値は変更され得るため、提示前に公式ページで確認し、未確認なら「要確認」と注記する）：
- **Google Gemini API**：1500リクエスト/日まで無料
- **Hugging Face**：多数の無料モデル（Llama、Mistral等）
- **Groq API**：無料枠あり（高速推論）
- **Together AI**：無料クレジット付き
- **Replicate**：無料枠あり
- **GitHub Copilot**（GitHub Actionsでの活用）

## Cloudflare活用のポイント：
- Workers：10万リクエスト/日まで無料
- Pages：無制限の静的サイトホスティング
- R2：10GB/月まで無料ストレージ
- D1：5GBまで無料のSQLiteデータベース
- KV：100,000読み取り/日まで無料
- Cron Triggers：定期実行の自動化

## Bash自動化の要件：
- **wrangler CLI**を使用したCloudflare操作
- **GitHub Actions**との連携によるCI/CD
- **curl/jq**によるAPI操作
- **環境変数**による設定管理（APIキーは無料枠のもののみ）
- **ログ出力**とエラーハンドリング
- **通知システム**（Discord webhook等の無料サービス）
- **無料APIの制限管理**（レート制限、日次上限の監視）

## 評価基準：
- 実現可能性（技術的・時間的・無料枠内）：30%
- 収益性（月10万円の現実性）：20%
- 自動化レベル（bash実装の容易さ）：15%
- エンゲージメント・リテンション（継続利用の仕組み）：15%
- 保守性（エラー耐性・監視）：10%
- 競合優位性（モート・差別化の持続性）：10%

## 追加指示：
- ニッチだが需要のある分野を狙う
- 日本市場に特化したアイデアも含める
- コンテンツの品質を保ちつつ量産できる仕組みを重視
- プラットフォームの規約に違反しないモデルのみ提案
- **完全無料のツールとAPIのみを使用（初期投資ゼロ）**
- Cloudflareの無料枠を最大限活用する設計
- **すべての操作がbashスクリプトで完結する設計**
- **エラー時の自動リトライとフォールバック機構**
- **定期的な健全性チェックとレポート生成**
- **ユーザーが使い続けたくなる習慣ループ・報酬設計を含めること**
- **競合の強みに対する具体的なカウンター戦略を含めること**
- **ネットワーク効果・データ蓄積等による競争優位の持続性を考慮すること**

## エラー・例外時の対処

- 無料枠だけでは成立しない案しか浮かばない: その案は出さず、条件を満たす別案に置き換える。10案に満たない場合は不足数と理由を明記する。
- ユーザーが有料ツールの併用を許可した場合: 有料部分を案ごとに明示し、評価基準の「実現可能性（無料枠内）」を減点要素として扱う。
- 月10万円の根拠を置けない案: 収益性は低評価にし、見込み額に「根拠なし」と書く。数字を作らない。
- 規約違反の疑いがある案（スクレイピング禁止サイトの利用等）: 提案から除外する。
