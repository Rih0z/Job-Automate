# モデル振り分け方針の詳細（第1〜9節）

SKILL.md の手順から参照する本体。節番号は SKILL.md の「第N節」と対応する。

## 目次

- 第1節 最上位方針
- 第2節 まず確認すべき対象
- 第3節 CLAUDE.md に反映すべき内容
- 第4節 司令塔が担当するタスク
- 第5節 低コストモデルに任せるタスク
- 第6節 高コストモデルに任せるタスク
- 第7節 カスタムエージェント設定方針
- 第8節 Skills 更新方針
- 第9節 委任指示テンプレート

## 1. 最上位方針

前提: プロジェクトに issue 用のフォルダや起票手順(CLAUDE.md や README に記載されたもの)がある場合に限り、第2節で対象が存在しないときその手順で起票する。無い場合は起票せず、報告に構成案を書いてユーザーに確認する。

すべての業務において、まず作業の難易度、影響範囲、リスク、コストを判断する。

- 簡単で定型的な実行作業は低コストモデル（Sonnet相当）に任せる。
- 複雑で高度な判断を伴う実行作業は高コストモデル（Opus相当）に任せる。
- 司令塔（メインエージェント／main orchestrator）は、難しいタスク、影響範囲が広いタスク、または全体方針の検討が必要なタスクにおいて、設計・判断・統合を担当する。
- 高コストモデルは、必要な場合のみ使用する。
- 低コストモデルで十分な作業に高コストモデルを使わない。
- 司令塔は、Claude.md、Skills、サブエージェント設定の整合性を常に確認する。
- 司令塔は、必要に応じて低コスト/高コストモデルに渡すための明確な作業指示を作成する。

---

## 2. まず確認すべき対象

最初に、プロジェクト内の以下を確認してください。

- Claude.md
- .claude/ 配下の設定
- .claude/agents/ 配下のカスタムエージェント
- .claude/skills/ 配下のSkills
- 関連するルールファイル、README、開発手順、サポート手順
- 既存のモデル使い分けルール
- 既存のレビュー、ファクトチェック、NDAチェック、セキュリティ確認ルール

存在しない場合は、推測で完了扱いにせず、必要なファイル構成案を示してください。

---

## 3. Claude.mdに反映すべき内容

Claude.mdには、すべての業務に共通する上位ルールとして、以下を整理してください。

- このプロジェクトの目的
- すべての業務に適用するモデル運用方針
- 司令塔 / 低コストモデル / 高コストモデル の役割分担
- 司令塔を使うべき条件
- 低コストモデルを使うべき条件
- 高コストモデルを使うべき条件
- 高コストモデルを使わない条件
- Skillsの利用方針
- カスタムエージェントの利用方針
- セキュリティ、NDA、コンプライアンス確認方針
- 実装、調査、サポート、資料作成、レビューに共通する品質基準
- 作業完了前の確認チェックリスト（上の「完了の判定」を、そのプロジェクトの作業に合わせて書き換えた 3〜5 項目。項目ごとに確認方法を添える）

Claude.mdは、特定の記事作成やブログ更新に限定せず、すべての業務に適用できる汎用ルールとして整理してください。

---

## 4. 司令塔が担当するタスク

司令塔は、以下のようなタスクで介入してください。

- 全体方針の検討が必要なタスク
- 作業方針や実装方針を決める必要があるタスク
- 複数案を比較して判断する必要があるタスク
- 複数ファイル、複数Skills、複数エージェントに影響するタスク
- Claude.md、Skills、カスタムエージェント設定の変更を伴うタスク（**変更の実施・採否の判断は常に司令塔が行う**。低コスト・高コストモデルに委任してよいのは、現状の調査、整合の確認、修正案の作成までで、ファイルへの反映は司令塔が行う。これが skill 変更の担当についての唯一の規則で、SKILL.md の閾値表(行 1 が最優先で、セキュリティ・NDA・顧客影響が絡んでも変わらない)と第5・6節もこれに揃える）
- 顧客影響、業務影響、セキュリティ影響が大きいタスク
- サポート回答や社外向け説明など、品質リスクが高いタスク
- ファクトチェック、NDAチェック、一次情報確認が必要なタスク
- コスト、品質、納期、リスクのバランス判断が必要なタスク

司令塔は、すべての実行作業を自分で抱え込まないでください。
作業を分解し、簡単な実行は低コストモデルへ、複雑な実行は高コストモデルへ委任してください。

---

## 5. 低コストモデルに任せるタスク

低コストモデルには、簡単で定型的な実行作業を任せてください。

例:

- 軽微な文章修正
- 要約
- 初期ドラフト作成
- 目次作成
- 用語説明
- 表記ゆれ修正
- トーン調整
- 定型的なチェック
- ログやメッセージの整理
- FAQ案の作成
- サポート回答の初期案作成
- 簡単なコード修正
- 既存ルールに沿った定型実装
- README、HTML、PPTXなどの初期生成
- Claude.mdやSkillsの一部の修正案の作成（案を作るだけ。ファイルへの反映と採否は司令塔が行う。第4節）

ただし、作業中に判断が難しい問題、設計変更、セキュリティ懸念、NDA懸念、複数ファイル間の矛盾、顧客影響が発生した場合は、司令塔に戻してください。

---

## 6. 高コストモデルに任せるタスク

高コストモデルには、複雑で高度な判断を伴う実行作業を任せてください。

例:

- 複雑な実装方針の検討
- 複数ファイルにまたがるコード変更
- 技術的に難易度の高い調査
- 障害原因の複雑な分析
- 顧客影響の大きいサポート回答レビュー
- 複数情報を統合した判断
- セキュリティ、NDA、コンプライアンス観点を含むレビュー
- 重要な社内外向け文書の最終確認
- 複数Skillsを横断する再設計の調査と案の作成（方針の決定と反映は司令塔。第4節）
- カスタムエージェント構成の大幅な見直しの調査と案の作成（同上）
- Claude.md全体に影響する大幅改訂の調査と案の作成（同上）
- 品質リスクが高い成果物の確認

高コストモデルは高コストであるため、単純な編集、要約、定型変換、初期ドラフト作成、軽微な実装、既存ルールに従うだけの作業には使用しないでください。

高コストモデルを使う場合は、必ず以下を明確にしてください。

- なぜ低コストモデルでは不十分か
- 高コストモデルに任せる範囲
- 期待する成果物
- 完了条件
- 司令塔が最終確認すべき観点

---

## 7. カスタムエージェント設定方針

必要に応じて、以下のようなカスタムエージェントを設計してください。

### orchestrator（司令塔）

目的:
高難度タスク、方針検討、モデル選択、作業分解、統合レビューを担当する。

使用条件:
- 全体方針の検討が必要
- 複数の作業やファイルに影響する
- Claude.md、Skills、エージェント設定に影響する
- コスト、品質、リスクの判断が必要

主な役割:
- 作業目的の整理
- タスク分解
- 低コスト/高コストモデルへの委任判断
- 実行指示作成
- 結果の統合レビュー
- Claude.md、Skills、エージェント設定との整合性確認

### executor（低コスト実行担当）

目的:
簡単で定型的な実行作業を低コストに処理する。

使用条件:
- 作業が定型的
- 既存ルールに従えばよい
- 判断の難易度が低い
- 失敗時の影響が小さい

主な役割:
- 初期ドラフト
- 要約
- 軽微な修正
- 定型チェック
- 簡単な実装
- ログ整理
- READMEや資料の初期生成

### specialist（高コスト実行担当）

目的:
複雑で高度な判断を伴う実行作業を担当する。

使用条件:
- 複雑な実装判断が必要
- 技術的リスクが高い
- 顧客影響や業務影響が大きい
- 複数ファイルや複数システムの整合性が必要
- セキュリティ、NDA、コンプライアンス確認が必要

主な役割:
- 複雑なコード変更
- 高度な調査
- 障害解析
- 最終レビュー
- リスク判断
- 高品質な統合案作成

---

## 8. Skills更新方針

既存Skillsを確認し、以下の観点で更新してください。各観点は「はい / いいえ」で答えられる形で判定し、「いいえ」の Skill だけを更新対象にします。判定の根拠として、該当箇所を `ファイル名:行番号` で示してください。

- 目的が明確か
- 入力と出力が明確か
- 実行手順が再現可能か
- 他のSkillsと重複していないか
- Claude.mdの方針と矛盾していないか
- 司令塔 / 低コストモデル / 高コストモデル の役割分担と整合しているか
- セキュリティ、NDA、ファクトチェックの条件が明確か
- 定型業務として再利用可能か

繰り返し発生する業務は、可能な限りSkills化してください。
ただし、方針判断や高リスク判断をSkillだけで自動化しないでください。

---

## 9. 司令塔から実行モデルへ渡す指示テンプレート

司令塔が低コスト/高コストモデルに作業を委任する場合、以下の形式で指示を作成してください。

```markdown
## 作業指示

### 担当モデル
低コストモデル / 高コストモデル

### 低コストモデルでは不十分な理由
（高コストモデルに任せる場合は必須。低コストモデルに任せる場合は「該当なし」）

### 作業目的
...

### 背景
...

### 入力情報
...

### 実行範囲
...

### 実行しない範囲
...

### 期待する出力
...

### 使用すべきSkills
...

### 注意事項
- セキュリティ:
- NDA:
- ファクトチェック:
- コスト:
- 既存ルールとの整合性:

### 完了条件
...

### 司令塔が最終確認すべき観点
（返却後に司令塔が確かめる点。例: 変更範囲が「実行範囲」内か、根拠が引用されているか、セキュリティ・NDA の懸念が無いか）
```

第6節の 5 項目との対応: 「低コストモデルでは不十分な理由」「実行範囲」（任せる範囲）「期待する出力」「完了条件」「司令塔が最終確認すべき観点」。
