# テスト結果レポートのひな形

SKILL.md「テスト結果レポート」の具体形。最終応答はこの 3 部構成で毎回同じ順に書く。

## 1. 実行結果サマリー

| 項目 | 内容 |
|---|---|
| 対象 URL / 環境 | 開発 / ステージング |
| 実施日時 | |
| PASS / FAIL / 未実施 | 実行した項目の件数(例: 実行 6 項目で 4 / 1 / 1) |
| 対象外 | 選ばなかった項目の番号一覧(件数には含めない。例: 5〜6、8〜15、17〜19) |
| 主なバグ・課題 | 1 行ずつ |
| 性能指標 | FCP / LCP / CLS などの測定値(合否は基準指定時のみ) |

## 2. 詳細テスト結果

| # | テスト項目 | 結果 | 期待値 | 実際の値 | エビデンス(ファイル名) | 改善提案 |
|---|---|---|---|---|---|---|
| 1 | ページロード | PASS | エラーなし | エラーなし | pageload_initial_YYYYMMDD_HHMMSS.png | - |

- FAIL は期待値と実際の値を必ず書く。
- 未実施は理由を「実際の値」欄に書く(例: 環境不備、対象機能なし)。
