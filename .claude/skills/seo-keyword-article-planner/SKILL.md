# SEO キーワード選定→記事構成一括出力

## 前提・使い方

### 入力

- **テーマ**(必須): 記事を書く領域と読者。ユーザーが指定しなければ、既定の例「個人事業主向け会計SaaS・確定申告」を使うか確認する。以降の手順で例として出る会計SaaS・確定申告の記述は、テーマに応じて置き換える。
- **選定済みキーワード**(任意): 指定があればステップ1の選定を飛ばす。
- **検索数・難易度の数値**(任意): Google キーワードプランナー等の数値。

### 前提

- Web 検索ツール(WebSearch / WebFetch)が使えることが前提(allowed-tools で宣言済み)。使えない場合は検索結果を前提にした項目を「未確認」と明記し、推測で数値を埋めない。
- 検索数・キーワード難易度は Web 検索だけでは正確に取れない。ユーザーが数値を提供した場合はそれを使い、無い場合は「推定(根拠: ○○)」と区別して書く。
- 詳細は `references/` に分離している。ステップ2の前に `references/article-outline-template.md`(A〜F)を、出力前に `references/outline-scorecard.md`(採点表)を Read する。
- 流れ: ステップ1〜2(キーワード選定と記事構成)は一括で出力する。ステップ3(競合深掘り)はユーザーが求めたときだけ別途実行する。

### 使用例

使用例1:「確定申告でブログ記事を書きたい。キーワード選定から構成案まで出して」 → テーマは既定の例と一致 → ステップ1で候補を調べて3つ選定 → ステップ2で各キーワードの記事構成(A〜F)と実装ガイドライン → 採点表で自己点検 → 実装優先順位まで一括出力。続けて「競合も深掘りして」と言われたらステップ3を実行する。

使用例2:「『青色申告 65万円控除 条件』で記事を書く。構成案だけ欲しい」 → キーワードが指定済みなのでステップ1の選定を飛ばし、そのキーワードでステップ2以降を実行する。

使用例3:「在宅ワーカー向けの腰痛対策グッズで、狙い目キーワードと構成案を出して」 → テーマを入力として受け、選定条件の季節性は「ピーク時期があるか」として扱う(通年需要なら「季節性なし」と明記して条件から外す) → ステップ1〜2を実行する。

使用例4(失敗系):検索ツールが使えない環境で「確定申告のキーワードを選んで」 → 検索数・競合・最新制度の項目を「未確認」とし、数値を作らない → 構成案(A〜F)は書けるので書き、採点表では確認不能な項目を「未確認」と理由つきで示し、末尾に手動確認を依頼する項目の一覧を付ける。

### 役割とミッション

あなたは10年の経験を持つSEOコンサルタント兼コンテンツマーケターとして、入力で受け取ったテーマ(例: 個人事業主向け会計SaaS・確定申告)に関する戦略的コンテンツ企画を実行する。ドメインパワーの弱い個人ブログでも上位表示可能な、収益性の高いキーワードを3つ選定し、それぞれの完全な記事構成を提案する。

### ステップ1: 戦略的キーワード選定

#### 選定条件

- **月間検索数**: 200-2,000回（適度な需要があり競合が激しくない範囲）
- **競合分析**: 上位10サイトのうち3つ以上が個人ブログ・中小サイト
- **商用意図**: 高い（テーマの商品・サービスの利用につながりやすい。例: 会計SaaS）
- **季節性**: テーマにピーク時期がある場合は、そこにピークがあること（例: 確定申告なら1-3月）。通年需要のテーマでは「季節性なし」と明記して条件から外す
- **キーワード難易度**: 30-50/100（中程度）

#### 必須分析項目

各キーワードについて以下を調査する。

1. **検索意図の詳細分析**（情報収集・比較検討・購入検討のどの段階か）
2. **競合サイトの弱点**（コンテンツの隙間や更新の古さ）
3. **ユーザーペインポイント**（解決すべき具体的な悩み）
4. **マネタイズ可能性**（CVRの高さ予想）

#### 検証ゲート（記事構成に進む前）

3つのキーワードそれぞれについて、次の採否表を埋めてから、ステップ2に進む。条件を満たさないキーワードは差し替える。

| キーワード | 月間検索数(出典 or 推定) | 難易度(出典 or 推定) | 上位10のうち個人・中小サイト数 | 商用意図 | 季節性 | 採否と、緩めた条件 |
|---|---|---|---|---|---|---|
| | | | | | | |

### ステップ2: 完全記事構成作成

選定した3つのキーワードそれぞれについて、以下の A〜F と実装ガイドラインを含む完全な記事構成を作成する。

A〜F の項目と実装ガイドライン(E-A-T強化・ユーザビリティ・差別化)は `references/article-outline-template.md` にある。これを Read して全項目を埋める。要点:

- **A. 記事基本情報**: 対象キーワード・想定文字数・ペルソナ・検索意図・競合優位性
- **B. タイトル・メタ設定**: H1、サブタイトル3案、メタディスクリプション、スラッグ案
- **C. 詳細見出し構成**: H1〜H3 の階層と導入・まとめ・CTA
- **D. 各セクション詳細設計**: H2・H3 ごとの執筆目的・内容・文字数・挿入要素・SEO要素
- **E. マネタイズ戦略**: CTA 配置、誘導文言、成約率向上策、離脱防止策
- **F. 技術的SEO要素**: 構造化データ、内部リンク、画像最適化、表示速度

#### 完成度の採点(出力前の自己点検)

A〜F の完成度を `references/outline-scorecard.md` の採点表(○=2 / △=1 / ×=0、12 点満点)で採点する。合格は合計 10 点以上かつ × が 0 件かつ A・C・D がいずれも ○。不合格なら該当セクションを直してから出力する。結果は各【記事構成N】の末尾に1行表で付ける。

### 出力形式

以下の順序で出力する。

**【キーワード分析結果】**
選定した3つのキーワードの詳細データ(上記の採否表を含む)

**【記事構成1】**
1つ目のキーワードの完全な記事構成(末尾に採点表の結果)

**【記事構成2】**
2つ目のキーワードの完全な記事構成

**【記事構成3】**
3つ目のキーワードの完全な記事構成

**【実装優先順位】**
3記事の制作優先順位と理由

**【競合調査の記録】**
確認した上位10サイトを、次の形式で各キーワード分まとめて付ける。

| 順位 | URL | 種別(個人 / 中小 / 大手) | 最終更新の目安 | 弱点・隙間 |
|---|---|---|---|---|
| | | | | |

### 特別指示

- Web 検索ツールで実際に検索し、上位10サイトを確認して競合分析を行う(確認した URL を上記の記録表に書く)
- 実行時点のテーマに関する最新情報(例: 確定申告なら制度変更・申告期限など)を検索で確認して反映する。確認できなかった情報は「要確認」と書く
- 数値の書き方: 検索で確認した数値は「数値(出典 URL)」、確認できない数値は「約○○(推定・根拠: ○○)」と書き分ける
- 初心者にも分かりやすい構成を心がける
- 収益化(アフィリエイト等)を最大化する導線設計
- 記事公開後の効果測定方法も提案
- 事実(検索で確認したデータ・出典付きの数値)と推測・推定は区別して書く。出典のない数値を断定しない

### 判定基準とフォールバック

- 成功の基準: 「選定条件」を満たすキーワードが3つ揃い、各キーワードに A〜F の全項目が埋まり、採点表の合否が「合格」(または理由つきの「条件付き」)であること。
- 条件を満たすキーワードが3つに満たない場合: 最も近い候補で補い、どの条件(検索数・難易度・競合構成など)を緩めたかを採否表に明記する。無理に3つ揃えるために数値を作らない。
- 検索が使えない・競合サイトを開けない場合: 該当項目を「未確認」とし、ユーザーに手動確認を依頼する項目の一覧を末尾に付ける。
- ユーザーが選定済みのキーワードを指定した場合: ステップ1の選定を飛ばし、そのキーワードでステップ2以降を実行する。

## ステップ3: 競合分析深掘り

起動条件: ステップ1〜2の出力後に、ユーザーが競合の深掘りを求めたとき。

選定したキーワードの競合サイトを詳細分析し、勝利戦略を立案する。

### 分析項目

- 上位10サイトの記事構成分析
- コンテンツの深さと網羅性
- ユーザビリティ要素
- 更新頻度と鮮度
- バックリンク状況(Web 検索だけでは取れない場合は「未確認」とし、推測で書かない)

### 戦略立案

- 競合を上回るコンテンツ戦略
- 狙い目の検索意図の隙間
- 差別化可能なユニーク要素

## 実行時のコツ

1. **実行の区切り**: ステップ1〜2は一括で出力し、ステップ3は結果を見たユーザーの依頼を受けてから別に実行する
2. **具体例の要求**: 「○○のようなキーワード例を10個」など具体的に指示する
3. **追加質問の活用**: 結果を見て更なる深掘りを依頼する
4. **データの検証**: 提案されたキーワードを別途キーワードプランナー等で確認する
