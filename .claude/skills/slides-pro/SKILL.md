# 企画書mdファイルからの16:9比率プレゼンテーションスライド生成プロンプト（プロフェッショナル版 v4.1）

完全な HTML/CSS/JS テンプレート・品質チェック・機械検証コマンドは、この skill の `references/output-structure.md` に自己完結で収めてある。**スライド生成では、まずこの references/output-structure.md を Read し、そのテンプレートをそのまま土台に使う**（他のリポジトリにコピーしても、SKILL.md と references/ だけで生成できる）。

任意の拡張: このリポジトリには、より詳しい原本 `workflows/content-creation/slides-pro.md` と、対応するレビュー用 skill `review-slides` がある。あれば原本を併せて Read し、テンプレート・ガイドラインを省略・改変せず適用してよい。無い環境では原本への言及は読み飛ばし、レビューの案内も省く（原本が無くても生成は止まらない）。

## 何をするか

ベテランITコンサルタントの視点から最適化された、企画書の md ファイルから 16:9 比率のプレゼンテーション
スライドを HTML と CSS で自動生成するシステム。実際のビジネスプレゼンテーションで求められる要素を網羅し、
視認性と操作性を最大化する。

## 絶対ルール（v4.1、詳細は原本参照）

1. CSS変数（`var(--xxx)`）は使用禁止 → 直接カラーコードを記述
2. すべてのテキスト要素に明示的な `color` を指定
3. 背景色と文字色のコントラスト比 4.5:1 以上を確保
4. 1スライドの情報量を制限（箇条書きトップレベル5項目以内・ネスト含み10項目以内・テーブル6行以内・
   カード4枚以内・段落テキスト3段落計150文字以内）→ 超えたらスライドを分割（フォント縮小で詰め込まない）
5. スクロールバーを必ず有効化（`.slide-content` に `overflow-y: auto`、長い場合の保険）

## 生成前の事前処理（必須）

1. 現在の日付を取得し、タイトルスライド・最終スライドの作成日に使用する。取得は、実行環境が提示する今日の日付があればそれを使い、無ければ WebSearch で確認する。どちらでも確定できないときは、ユーザーに日付を尋ねる(推測で書かない)
2. 日本語表記（例: 2026年8月27日）または英語表記でフォーマット

## 入力が使えないときの対処

- 引数の企画書 md が存在しない・読めない・空: 生成せず、パスの再指定を依頼する
- 原本 `slides-pro.md` が存在しない・読めない: 問題なし。`references/output-structure.md` の完全テンプレートで生成する(原本の内容を推測で補わない)
- `references/output-structure.md` が読めない: 生成せず、skill の配置が壊れている旨を報告する
- 企画書に見出し構造が無く、スライドへの分割単位が決められない: 分割案(スライド題名の一覧)を提示して確認を取る

## 生成手順

1. `references/output-structure.md` を Read し、完全な HTML テンプレート（`<!DOCTYPE html>` から
   `</html>` まで、`PresentationManager` クラス・キーボード/タッチナビゲーション・PDF出力・
   印刷用 `@media print` スタイルを含む）をベースに使用する（原本 `slides-pro.md` があれば併読してよい）
2. 引数で渡された企画書 md ファイルの内容を Read し、内容をスライドへ構造化する
3. フォントサイズガイドライン（h1: 36px/タイトルh1: 48px、h2: 26px、h3: 20px、本文: 20px、補足: 16px）
   を厳守する
4. 情報量ガイドラインに従いスライドを分割する（多すぎる情報を1スライドに詰め込まない）
5. 最終スライドは「Thank You」で終わらせず、`.summary-slide` 形式で重要ポイント3〜5個 + 各ポイントの
   参照ページ番号（`.summary-page` → p.X）+ Next Action（あれば）を含める
6. 生成した単一 HTML ファイルを、入力の企画書 md と同じディレクトリに `<企画書のファイル名(拡張子なし)>-slides.html` として Write する。ユーザーが保存先を指定した場合はそれに従う

## 生成後の品質チェックリスト（原本より、必ず確認）

- 視認性: タイトルスライドの文字が白色、通常スライドの文字が濃い色、カード内テキストが読める、
  CTAボックス内テキストが白色、遠くからでも読めるフォントサイズ
- レイアウト: 箇条書きが5項目以内、テーブルが6行以内、コンテンツがはみ出していない、スクロールバーが機能する
- 最終スライド: 「Thank You」だけで終わっていない、重要ポイント3〜5個、参照ページ番号あり、Next Action記載
- 機能: ← → キーでスライド移動、PDF出力ボタンが機能、プログレスバーが更新、スライド番号が正しい

## 機械検証（合格判定・必須）

目視のチェックリストだけで合格にしない。生成後に `references/output-structure.md` の「機械検証」節のコマンドを実行し、期待結果と一致することを確認する。代表例（`F` は生成した HTML のパス）:

```bash
grep -c 'var(--' "$F"                                # 期待: 0
grep -ciE 'color:[[:space:]]*white' "$F"             # 期待: 0
grep -c 'class="slide summary-slide' "$F"            # 期待: 1
grep -ciE 'thank you|ご清聴' "$F"                     # 期待: 0
```

期待結果と異なるコマンドが 1 つでもある、または上のチェックリストで外れた項目があれば、完了報告の前に HTML を直して再実行する(直し方は `references/output-structure.md` の「不合格時の扱い」)。完了報告には実行したコマンドと結果を添える。

## 出力 HTML の構造

タイトルスライド → 本文スライド(複数) → `.summary-slide` の順で、`<section class="slide">` を並べた単一 HTML にする。進捗バー・前後ボタン・スライド番号・PDF 出力ボタン・`PresentationManager`(キー/タッチ操作)を含む。各部位の断片と最小の骨子は `references/output-structure.md` を参照する。

## 禁止事項（原本より）

1. CSS変数 `var(--xxx)` の使用
2. `color: white` の曖昧な記述（`#ffffff` を使用）
3. 背景色と同系色の文字色
4. 1スライドに6項目以上の箇条書き
5. スクロールバーの無効化
6. 最終スライドを「ご清聴ありがとうございました」だけで終わらせる

## 使用例

- ユーザー: 「`plans/app-plan.md` からスライド作って」 → 日付を確認 → 原本テンプレートと企画書を Read → 情報量上限に収まるようスライドを分割 → `plans/app-plan-slides.html` を Write → 完全パスを報告する
- ユーザー: 「箇条書きが 8 個ある章をスライドにして」 → 5 項目以内になるよう 2 枚に分割する(フォントを縮めて 1 枚に詰めない)
- 失敗系: 「`plans/missing.md` からスライド作って」でファイルが無い → HTML を生成せず、パスの再指定を依頼する。「PowerPoint (.pptx) で欲しい」→ この skill の対象外（HTML 専用）と伝える。機械検証で `var(--` が 1 件以上出たら、直接カラーコードへ置換して再実行し、0 になってから報告する

## 出力後

生成した HTML ファイルの完全パスをユーザーに報告する。レビューが必要で `review-slides` skill がある環境では `.claude/skills/review-slides/SKILL.md` を使用する（別エージェントでの客観的レビュー、自己レビューしない）。
