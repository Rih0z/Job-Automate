# 論者への指示 (Step 2 で使う)

SKILL.md の Step 2 から参照される。共通部は 3 本に同一、役割部は論者ごとに変える。

## 共通部 (3 本に同一)

```
提案ファイル (絶対パス、必ず最初に全文 Read): <Step 1 の path>
repo root: <絶対 path>
出力: 各主張に <file>:<line> literal 引用 + 確信度 (VERIFIED / SUSPECTED / REFUTED)。
「なし」と判定する場合は調査した path を明記 (proof by absence を verdict にしない)。
運用制約 (literal): 読み取り専用 (コード変更・ファイル作成・プロセス操作・git 書込 禁止)。
<重い処理の実行中なら: repo 全体への再帰 grep 禁止、Grep は path+glob 限定、スクリプト/ビルド/テスト実行 禁止>。
会話履歴は与えられていない。期待される結論も与えられていない。Read した一次資料のみを根拠にすること。
```

## 役割部

| 論者 | 課すこと | 出力節 |
|---|---|---|
| 推進側 | 採用すべき最強の論証。不利な事実は「反対側が指摘しうる弱点」として明記した上で反論。効果を**数値**で予測 (一次データから) | 1 提案の分解 (実装済/未実装、行番号) 2 採用論拠 3 弱点と反論 4 Q1/Q2/Q3 verdict 5 最小実装案 + 再テスト設計 (何を測れば効果判定できるか) |
| 反対側 | 今すぐ採用すべきでない最強の論証。**提案の前提となる因果を一次データで検証** (原因帰属を数値で)。有利な事実は「推進側が主張しうる利点」として明記した上で反論 | 1 前提の事実検証 2 不採用論拠 3 利点と反論 4 Q1/Q2/Q3 verdict 5 代替案 (提案より先にやるべきこと、コスト昇順) |
| OSS 調査 + 中立裁定 | 賛否どちらの立場も与えない。OSS ごとに提案の各要素 (例: ①保存 ②クリア ③再開) の実装有無を表にし、本 repo 既存実装との差分を行番号で示す。5 観点で独立採点 (下の尺度と書式) | 1 OSS × 要素 表 2 既存実装との差分 3 5 観点評価 4 Q1/Q2/Q3 verdict 5 推奨 (採用 / 不採用 / 条件付き + 条件) |

## 5 観点評価の尺度と書式 (裁定役の 3 節)

各観点を 3 段階で採点する。採点は一次資料の引用が付いたものだけを根拠にする。

| 段階 | 基準 (1 行) |
|---|---|
| 良 | 提案はその観点を満たす。根拠の引用がある |
| 要注意 | 満たす可能性はあるが、条件付き、または一次資料で確認できない部分がある |
| 不可 | その観点に反する、または一次資料で反証された |

書式は観点ごとに 1 行、表で出す。

```
| 観点 | 段階 | 根拠 (file:line) | 確信度 |
|---|---|---|---|
| 1 対症療法でないか | 良 / 要注意 / 不可 | ... | VERIFIED / SUSPECTED / REFUTED |
| 2 超長期的に最適か | ... | ... | ... |
| 3 業界標準と整合するか | ... | ... | ... |
| 4 セキュリティ懸念 | ... | ... | ... |
| 5 既存実装を活かせないか | ... | ... | ... |
```

「不可」が 1 つでもあれば、5 節の推奨は「採用」にしない。
