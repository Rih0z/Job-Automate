# サムネイル画像生成 (Gemini + Claude 3ラウンド方式)

ブログ記事・動画のサムネイルを、画像生成AI(絵作りの創造性)と Claude(事実の確定・指示文・ブラウザ操作・レビュー)の分業で作る。この SKILL.md だけで手順を実行できる。さらに詳しい背景と落とし穴は原本 `workflows/content-creation/thumbnail-generation.md`(この repo にある場合のみ。無くても下記で足りる)。

## 前提

- 画像生成AI(Gemini 等)をブラウザで操作できること(Playwright MCP 等。MCP が未接続なら `mcp-server-setup` skill で接続するか、ユーザーに手動操作を依頼する)。
- 入力: 対象コンテンツ(記事/台本)、土台の実写真・素材、ブランド要素(マスコット/ロゴ)の**単体参照画像**。
- 出力: 最終サムネイル画像(形式・サイズ・保存先はユーザー指定に従う。指定が無ければ使用先の標準サイズを確認する)。

## 手順

**STEP 0 準備**: コンテンツの要点を数行に要約する。ブランド要素の単体参照画像と土台の実写真を用意する(第三者の顔が判別できる写真はぼかし/クロップしてから使う)。見出しに入れる固有名詞・数値は、一次情報から Claude が確定しておく。

**Round 1 土台生成(新規チャット)**: 実写真 + ブランド要素の単体参照画像を添付し、「素材とブランド要素を1枚に統合し、確定済みの見出し文言まで焼き込んだマスター画像を作る。実写部分はイラスト化・描き替えしない」旨を送る。出力をマスターとして保存する。

**Round 2 創造的仕上げ(新規チャット)**: Round 1 の出力 + ブランド要素の単体参照画像(Round 1 と同じセット)を添付。要点を数行で渡し「魅力を感じる仕上がりに」と短く指示する。細部は画像生成AIに任せる。

**レビュー**: Round 2 の出力を `review-thumbnail` skill のチェックリストで1項目ずつ確認する(可能なら文字可読性の機械チェックも併用)。自己レビューのみでの採用は禁止。

**Round 3 CTRフック追加 + 修正(新規チャット・毎回必須)**: Round 2 の出力(絵柄が崩れていたらその要素の単体参照画像も)を添付。指示は2〜3項目だけ。
1. 「見ると何が分かるか」を表す短いフック文言を、既存見出しと同等以上に目立つ文字で1つ追加(文言は Claude が確定して書き込む)。
2. レビューで見つけた問題の修正(無ければ「検出された問題なし」と明記)。
3. 大きさ・色・装飾の細かい指定はしない。
問題が無くても Round 3 は省略しない。出力後にもう一度レビューする。

## 守ること

- 各ラウンドは必ず新規チャットで実行し、ブランド要素の単体参照画像を毎回添付する(同一チャットの追加依頼は無視されやすく、統合画像だけ渡すとブランド要素が別物に描き替わることがある)。
- フック文言・固有名詞・数値は Claude が一次情報から確定する。生成AIへの丸投げ・空欄送信・捏造は禁止。
- Round 2/3 の指示は短く保つ(長文は崩れやすい)。
- 実写真内の文字(看板・銘板)は誤生成されやすいので元写真と照合する。マスコットの複製・見出しの増殖・実写に無い装飾の描き足しも確認する。

## 失敗時の判定と対処

| 状況 | 対処 |
|---|---|
| Round 2 が同一素材で2回連続、**異なる種類**の新規欠陥になった | 3回目はやらず、フォールバック(下記)へ切り替える |
| 同じ種類の欠陥が2回連続 | 指示文にガードレール文言(禁止事項)を1つ足して続ける |
| Round 3 後のレビューで機械レビュー起因の修正が2回で解消しない | Round 1 からやり直すか、フォールバックへ |
| 画像生成AIが拒否応答 | 新規チャットで1回だけ再送。2回連続なら Round 2 から、ブランド要素の単体参照画像を添付してやり直す。それでも駄目ならフォールバック |
| ブラウザ操作ができない / 利用制限に達した | ユーザーに状況を報告し、手動操作を依頼するかフォールバックへ |

**フォールバック**(実写真が無い、または生成AIが使えない): テンプレート+要素の機械的レイアウトで下地を作り、可能なら Round 1相当→Round 2相当の2段階を通してから採用する。生成AIが完全に使えない場合のみ機械合成を仮採用とし、「仮運用で進めた」事実を報告に明記して完成扱いにしない。

## 使用例

ユーザー: 「この記事のサムネ作って。マスコットの画像はこれ」
→ 記事の要点と固有名詞を確定 → Round 1(実写真+マスコット)→ Round 2(短い仕上げ指示)→ `review-thumbnail` で確認 → Round 3(フック文言追加)→ 再レビュー → 最終画像と、各ラウンドの結果・検出した問題・採用判断を報告。

## 完了報告に含めること

最終画像の保存先、実行したラウンドと各ラウンドで検出した欠陥・対処、`review-thumbnail` の結果、フォールバックや仮運用を使った場合はその旨。
