# 段階的調査ワークフロー(ゲート付き反復)

## 前提条件

- Python 3 が実行できること。レビュー連携は `.claude/skills/_shared/scripts/` と `.claude/skills/_shared/review-record.schema.json` に依存する。他リポジトリへ移す場合は `_shared` も一緒に配置する
- Web 検索(Phase 1)が使えない環境では、その旨を調査の限界に明記して Phase 2 へ進む
- 別エージェントを起動できること(段階ゲートとレビューに使う)

## 適用対象

複数の手がかりを反復的に辿って結論に至る必要がある調査(原因分析・技術検証・競合調査等)。単発で1つの資料を読んで答えるだけの依頼には使わない(過剰な手順化を避ける)。

## Phase 0: 状況把握

対象について既にある情報(ログ・資料・過去の調査結果)を確認する。**推測せず、まず手元の一次情報を読む**。

## Phase 1: 過去事例・公知情報の先行調査

内部の知見だけで結論を出す前に、Web検索で既知の事例・公式見解・先行情報を確認する(検索語は固有名詞・機微情報を含まない技術的なキーワードに絞る)。

## Phase 2: 調査方針の策定

Phase 0-1の所見から、調査の方向性(何を・どの順で確認するか)と**終了条件**を決める。終了条件は次の3系統:
1. 十分な確信度に到達(根拠の直接性で判定、下記「確信度キャップ」参照)
2. 反復回数の上限(目安: 8回。無限ループ防止)
3. 追加データが必要で、これ以上は進められない(ユーザーへ差し戻し)

## Phase 3: ユーザー承認(1回のみ)

調査方針と終了条件をユーザーに提示し、承認を得る。**承認は最初の1回のみ**。承認後の各段階は自走し、段階ごとの再承認は求めない。ユーザーへの再相談は以下3トリガーのみに限定する: 重大な分岐判断が必要 / 手詰まり / 追加データが必要。

## Phase 4: 段階ゲート付き反復(承認後は自走)

```
段階 = 1
while 終了条件を満たさない:
  4a. 実行: 当該段階で確認すべき情報を調べる
  4b. 記録: 得られた事実と、そこからの解釈を分けて記録する(事実と推測を混在させない)
  4c. 次方針: 所見から次に何を調べるかを決める(または終了候補と判断)
  4d. 段階ゲート: 別エージェントが次の軽量基準でPASS/FAILを判定する。(1) この段階の結論が、4bに記録した事実に直接の根拠を持つ (2) 事実と解釈が分かれて記録されている (3) 否定結論なら網羅的な確認を実施済み。1つでも満たさなければFAIL
  4e. 判定: PASS→継続 / 終了条件該当→Phase 5 / 重大分岐・手詰まり→ユーザーへ差し戻し / FAIL→指摘された不足(根拠の欠落等)を同じ段階で補って再判定。同じ指摘でFAILが続くときは、調べ方を変える(別の一次情報を当たる等)。それでも解消しなければ手詰まりとしてユーザーへ差し戻す
```

**段階記録の保存先と形式**: 4b の記録は、段階ごとに作業ファイル `.tmp/staged-investigation/<調査名>/stage-NN.md`(NN は 01 から)へ追記保存する(ディレクトリが無ければ作る。`.tmp/` は作業領域であり、リポジトリの追跡対象にしない)。各ファイルの見出しは固定で、上から順に次を置く。再開時はこのファイル群を読んで続きから進める。

```
# 段階 NN
## 事実(観測したもの・出典付き)
## 解釈(事実からの推論)
## 次方針
## 段階ゲート判定(PASS / FAIL と指摘)
```

結論に影響しない細かい確認までは記録しなくてよい。この段階記録は調査中の作業用であり、review-history への永続化(下記「レビュー連携」)とは別物で、永続化は Phase 5 完了時の1回だけ行う。

## Phase 5: レポート作成

段階記録(`stage-NN.md`)を材料に、次の見出し構成でレポートを作成する(見出し名と順序は固定)。

```
# <調査対象> 調査レポート
## 1. 結論と確信度
## 2. 観測結果(事実)
## 3. 解釈
## 4. 代替仮説と棄却理由(最低2件)
## 5. 調査の限界
## 6. 次のアクション
## 7. 参照した一次情報
```

各見出しに書く内容は次のとおり:
- 観測結果と解釈を分離して記載する(2 と 3)
- **確信度レベル**を明示する(証拠の直接性に応じて上限をキャップする)。レベルと上限は次の表に従う
  - 高: 直接証拠(該当ログの該当行・該当設定値・公式文書の該当記述)がある
  - 中: 直接証拠は無いが、独立した複数の状況証拠が同じ結論を指す。上限は「中」
  - 低: 状況証拠が1系統のみ、または推測を含む。上限は「低」
  - 未確定: 追加調査が必要。結論として断定しない
- **代替仮説を最低2件、棄却理由付きで**併記する(1つの結論に飛びつかない)
- 調査の限界(確認できなかった点・ツール上の制約)を明示する
- 次のアクション(推奨される対処・追加確認事項)

**不在の主張への注意**: 「〜は存在しない」「原因ではない」という否定結論に高い確信度を付けるには、それを裏づける網羅的な確認を実施済みであることを条件とする。網羅的な確認を経ていない否定結論には高い確信度を付けない。

## 使用例

- ユーザー: 「この障害の原因を腰を据えて調査して」 → Phase 0 で手元のログと過去記録を読む → Phase 1 で公知事例を検索 → Phase 2 の方針と終了条件を提示し、ユーザーが承認 → Phase 4 を自走(各段階で別エージェントがゲート判定) → Phase 5 で確信度付きレポート。原因の候補Aに直接証拠があれば確信度「高」、状況証拠のみの候補Bは「中」以下、代替仮説2件を棄却理由付きで併記する
- 承認後に新しい重大な分岐(調査対象の範囲が倍になる等)が見つかった場合は、自走せずユーザーに差し戻して方針の再承認を得る

## 失敗時の対処

- Web 検索や WebFetch が失敗する: 検索語を変えて1回再試行し、それでも失敗なら調査の限界に記載して続ける
- `list_review_records.py` が該当なし: 過去記録なしとして進める。スクリプトが存在しない場合は `_shared` の配置を確認し、無ければ過去記録の参照を省略した旨をレポートに記す
- 反復が上限(目安8回)に達したが確信度が足りない: 到達できた確信度のまま Phase 5 に進み、不足している追加データを次のアクションに書く

- 別エージェントを起動できず段階ゲート(4d)やレビューを実施できない: 自己判定で代替せず、ゲート未実施の段階とレビュー未実施のレポートである旨を Phase 5 の「調査の限界」に明記し、ユーザーへ報告する

## レビュー連携

**過去レビュー記録の参照(Phase 0で行う)**: Phase 0(状況把握)の一部として、以下を実行し過去の同種調査の記録を検索する。ヒットすれば所見の入力として使う。

```bash
python .claude/skills/_shared/scripts/list_review_records.py --target "<調査対象>"
```

Phase 2の方針とPhase 5のレポートは、別エージェント(自己レビューではない)によるレビューを経てから次段階へ進む。

**永続化(Phase 5完了時)**: Phase 5のレビュー結果は、以下の review-record/v1 JSON（スキーマ: `.claude/skills/_shared/review-record.schema.json`）としても出力させ、`.claude/review-history/staged-investigation-workflow/` へ永続化する（各段階の逐次記録は上記 `.tmp/staged-investigation/` の作業ファイルで行い、review-history への永続化はPhase 5完了時の1回だけ行う）。`skill: "staged-investigation-workflow"`, `verdict` はレポートのレビューがPASS/FAILのどちらか、`criteria` は「事実/解釈の分離」「代表仮説の有無」等のレビュー観点、`sources_cited` は調査で参照した一次情報・URL一覧を入れる。

```bash
# レビューエージェントが出力したJSONを一時ファイルに保存した上で:
python .claude/skills/_shared/scripts/append_review_record.py <一時JSONファイルのパス>
```

**このスクリプトが成功（書き込み先パスを標準出力）するまで調査完了として報告しない**。検証エラー（必須フィールド欠落等で非ゼロ終了）の場合は、エラー内容に従ってJSONを修正し再実行する（強制の限界: プロンプト指示による実行そのものは確率的だが、スクリプト自体のスキーマ検証は決定的）。

## やってはいけないこと

- 推測で結論を出す(必ず一次情報・証拠に基づく)
- ユーザー承認なしにPhase 4(反復調査)へ進む
- 状態を保存せず中断する(再開できるよう、各段階の記録を `.tmp/staged-investigation/<調査名>/stage-NN.md` へ都度保存する)
- 状況証拠だけで高い確信度・断定的な否定結論を付ける
