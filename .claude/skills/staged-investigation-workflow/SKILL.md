# 段階的調査ワークフロー(ゲート付き反復)

## 適用対象

複数の手がかりを反復的に辿って結論に至る必要がある調査(原因分析・技術検証・競合調査等)。単発で1つの資料を読んで答えるだけの依頼には使わない(過剰な手順化を避ける)。

## Phase 0: 状況把握

対象について既にある情報(ログ・資料・過去の調査結果)を確認する。**推測せず、まず手元の一次情報を読む**。

## Phase 1: 過去事例・公知情報の先行調査

内部の知見だけで結論を出す前に、Web検索で既知の事例・公式見解・先行情報を確認する(検索語は固有名詞・機微情報を含まない技術的なキーワードに絞る)。

## Phase 2: 調査方針の策定

Phase 0-1の所見から、調査の方向性(何を・どの順で確認するか)と**終了条件**を決める。終了条件は次の3系統:
1. 十分な確信度に到達(根拠の直接性で判定、下記「確信度キャップ」参照)
2. 反復回数の上限(目安: 8回。無限ループ防止)
3. 追加データが必要で、これ以上は進められない(ユーザーへ差し戻し)

## Phase 3: ユーザー承認(1回のみ)

調査方針と終了条件をユーザーに提示し、承認を得る。**承認は最初の1回のみ**。承認後の各段階は自走し、段階ごとの再承認は求めない。ユーザーへの再相談は以下3トリガーのみに限定する: 重大な分岐判断が必要 / 手詰まり / 追加データが必要。

## Phase 4: 段階ゲート付き反復(承認後は自走)

```
段階 = 1
while 終了条件を満たさない:
  4a. 実行: 当該段階で確認すべき情報を調べる
  4b. 記録: 得られた事実と、そこからの解釈を分けて記録する(事実と推測を混在させない)
  4c. 次方針: 所見から次に何を調べるかを決める(または終了候補と判断)
  4d. 段階ゲート: 別エージェントが軽量基準(この段階の結論が事実に基づいているか等)でPASS/FAILを判定する
  4e. 判定: PASS→継続 / 終了条件該当→Phase 5 / 重大分岐・手詰まり→ユーザーへ差し戻し
```

各段階の結論を動かした重要な確認結果は、後から追える形で記録する(結論に影響しない細かい確認まで逐一記録する必要はない)。

## Phase 5: レポート作成

以下を含むレポートを作成する:
- 観測結果と解釈を分離して記載する
- **確信度レベル**を明示する(証拠の直接性に応じて上限をキャップする。例: 状況証拠のみで断定的な結論は付けない。直接証拠(該当ログの該当行・該当設定値等)があって初めて高い確信度を付けられる)
- **代替仮説を最低2件、棄却理由付きで**併記する(1つの結論に飛びつかない)
- 調査の限界(確認できなかった点・ツール上の制約)を明示する
- 次のアクション(推奨される対処・追加確認事項)

**不在の主張への注意**: 「〜は存在しない」「原因ではない」という否定結論に高い確信度を付けるには、それを裏づける網羅的な確認を実施済みであることを条件とする。網羅的な確認を経ていない否定結論には高い確信度を付けない。

## レビュー連携

Phase 2の方針とPhase 5のレポートは、別エージェント(自己レビューではない)によるレビューを経てから次段階へ進む。

## やってはいけないこと

- 推測で結論を出す(必ず一次情報・証拠に基づく)
- ユーザー承認なしにPhase 4(反復調査)へ進む
- 状態を保存せず中断する(再開できるよう、各段階の記録を都度保存する)
- 状況証拠だけで高い確信度・断定的な否定結論を付ける
