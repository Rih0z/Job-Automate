# サーバー初期設定 — SSH接続環境構築

## 前提条件
- ローカルに ssh クライアント (`ssh` / `ssh-keygen`) がある (Windows 10 以降・macOS・Linux は標準搭載)。
- 契約中のサーバープランが SSH 接続に対応している (非対応なら管理会社のプラン変更案内を伝える)。
- 管理会社固有の画面操作や設定項目名は版により変わる。確実に分からない箇所は断定せず、管理会社の公式ヘルプで確認するようユーザーに促す。

## 行動原則
- 秘密鍵 (`id_*` で .pub が付かないファイル)・パスワードを出力やファイルに書かせない。共有するのは公開鍵 (`.pub`) だけ。
- 本番サーバーを変更する操作の前に、現在の内容のバックアップを取る。
- 破壊的コマンド (削除・上書き同期の `--delete` 等) はユーザーの確認なしに提案しない。

## 手順

1. Claude Web版を利用して、自分の開発環境と借りているレンタルサーバーの環境をSSHで接続できる
   環境を構築する。

2. 以下のプロンプトパターンでユーザーから情報を受け取り、案内する。

### パターン1: SSH接続設定がまだの場合

```
[ブログアドレス]を[サーバー管理会社]レンタルサーバーで運用している。ssh接続がしたい。設定方法を教えて。
```

上記の依頼を受けたら、対象のレンタルサーバー管理会社が提供するSSH接続手順 (SSH鍵生成・公開鍵
登録・接続確認) を具体的に案内する。

1. 鍵を作る: `ssh-keygen -t ed25519 -f ~/.ssh/<サーバー用の名前>` (パスフレーズ設定を推奨)。
2. 公開鍵 (`~/.ssh/<名前>.pub`) の内容だけを、管理会社のサーバー管理画面の SSH 設定に登録する。
3. 接続を確認する: `ssh -i ~/.ssh/<名前> -p <ポート> <ユーザー名>@<ホスト名>`。
   成功判定は、サーバーのシェルのプロンプトが出ること。
4. 次へ進む条件は接続成功。失敗したら次の対処を順に試す。
   - `Connection refused` / タイムアウト: ホスト名・ポート (管理会社指定の場合あり)・サーバー側 SSH 有効化を確認。
   - `Permission denied (publickey)`: 登録した公開鍵が正しいか、`-i` で指定した秘密鍵が対応しているか確認。
   - `UNPROTECTED PRIVATE KEY FILE`: 秘密鍵の権限を `chmod 600 ~/.ssh/<名前>` にする。
5. 成功したら `~/.ssh/config` に `Host` 別名を登録しておくと以降の指示が短くなる。

### パターン2: SSH接続設定済みの場合

```
[ブログ名]を[サーバー管理会社]レンタルサーバーで運用している。sshの設定はしている。このブログに
ついて、claudeで管理できるようにしたい。ローカル環境で編集して、問題がなければサーバーに
アップロードする形である。このようなことはできる？できるなら環境構築を手伝って。
```

上記の依頼を受けたら、ローカル編集 → 検証 → サーバーへアップロードのワークフローが実現可能で
あることを説明し、必要なファイル同期・バックアップ体制の環境構築を支援する。

1. まず接続を確認する (`ssh <別名> 'echo ok'` で `ok` が返ること)。通らなければパターン1の手順に戻る。
2. アップロード前にサーバー側の現在の内容をローカルへバックアップする。
   例: `rsync -av <別名>:<サーバー側ディレクトリ>/ ./backup/` (rsync が無ければ `scp -r`)。
   バックアップのファイル数・サイズが想定どおりか確認してから次へ進む。
3. ローカルで編集し、反映前に差分を確認する (`rsync -avn` で転送対象だけ事前表示)。
4. ユーザーの承認後に反映する (`--delete` は付けない)。反映後に公開ページを開いて表示を確認する。

## 最終報告のテンプレート

最後に、設定した内容を次の形で短くまとめて返す。秘密鍵の中身は書かない。

```
ホスト別名: <別名>
接続確認: 成功 / 失敗 (失敗なら出たエラーと試した対処)
バックアップ先: <ローカルのディレクトリ> (ファイル数・サイズ)
同期コマンド: <rsync / scp のコマンド。--delete なし>
次の工程: server-automation へ引き継ぐ / 未完了の項目
```

ワークフロー構築 (バックアップ・記事更新・ファクトチェック等) は `.claude/skills/server-automation/SKILL.md`

## 使用例

- ユーザー: 「ブログを○○社のレンタルサーバーで運用している。ssh接続がしたい」
- 動作: パターン1 で鍵作成 → 公開鍵だけを管理画面に登録 → 接続確認 (シェルのプロンプトが出れば成功) → `~/.ssh/config` に別名登録 → 最終報告テンプレートで返す。
- 接続が通らない場合は上記のエラー別の対処を順に試し、解消しなければ管理会社の公式ヘルプの確認をユーザーに促す。
