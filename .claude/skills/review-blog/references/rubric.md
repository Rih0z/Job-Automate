# 採点基準の要点（原本の自己完結版）

本ファイルは、0-gate・4-gate・9-gate の判定と、第11項目の Must / Nice 減点を再現するのに必要な内容を持つ。原本 `workflows/content-creation/review-blog.md` が有る環境でも無い環境でも、採点の構造（観点・配点・ゲート・減点・判定・出力）は本ファイルで決まる。原本が有るときは、第1〜10項目の詳細チェックリストの補助として読み、本ファイルと食い違う細部は原本を優先する。原本が無いときは、原本未参照と補足コメントに書く。

## 1. 設定欄（採点前に記入）

| 軸 | 記入する項目 |
|---|---|
| A. プラットフォーム | 掲載先、既知の制約（絵文字・HTML タグ・Frontmatter・文字数）、絵文字ポリシー |
| B. 業界 | 業界規制、コンプライアンス制約、利益相反（COI）開示の要否 |
| C. 記事タイプ | 記事タイプ、想定読者層、記事の目的、外部主体への断定の有無 |
| D. 運用 | 文体ポリシー、目標スコア（100 点換算値）、出力粒度（完全版 / 最小版） |

記事が冗長でスコープ不明確と判断した場合は、採点前に執筆者へ「核心メッセージ・想定読者・スコープ・読者に取らせたい行動」を確認する。

## 2. 3 つのゲート（検出したら総合点に関わらず判定 D・公開不可）

| ゲート | 発動条件 |
|---|---|
| 0-gate | 掲載先固有の技術制約に違反し、投稿不能・表示崩れが起きる（例: 絵文字を受け付けない CMS に装飾絵文字がある、Frontmatter 必須項目の欠落、禁止 HTML タグ）。装飾絵文字は「成功」「失敗」「注意」などの文字か、`strong` や色付き要素に置き換えて再レビューする |
| 4-gate | 外部の企業・組織・個人の財務・採算性・戦略判断・性能・評判を、報道や伝聞などの二次情報だけで断定し、当事者の公式反論・否認の検索を行っていない。または反論があるのに本文で触れていない。または過去時点の主張を時点を示さず現在の文脈で引用している |
| 9-gate | 顧客名・NDA 対象情報・社外秘の無断記載、本人同意のない個人情報、著作権・ライセンス違反、業界規制の NG 表現（打消表示・出典・所感扱いのいずれも無い）、名誉毀損・差別的表現、対象読者が該当地域を含む場合の GDPR / CCPA 違反 |

4-gate の発動トリガー語: 財務系（赤字・黒字・採算性・破産など）、戦略系（「〜社は〜と判断した」「失敗した」など）、性能・評判系（最速・最低・業界標準など）、伝聞系（「複数の報道によれば」「内部関係者によれば」など）、固有名詞と断定の組合せ。通過条件は、断定的主張の抽出、公式反論検索の実施と記録、両論併記または「二次情報由来・一次ソース未検証」の脚注、過去時点の主張への時点明示。

## 3. 11 観点と配点（各 10 点、計 110 点）

| 11 | 技術評価の妥当性 | ベンチマーク・製品比較・実証実験を含む記事で重点評価（次節） |

## 4. 第11項目のサブセクション配点

| 略号 | サブセクション | 通常 | 整合性検証（戦略分析記事） | 軽量化（製品レビュー） |
|---|---|---|---|---|
| F | フェアネス（比較条件の公平性、チェリーピッキング、比較対象の選定理由） | 2.0 | 2.0 | 2.0 |
| Q | 定量性（数値、単位、ばらつき、サンプル数 n、有意性） | 2.0 | 2.0 | 1.0 |
| C | 評価基準の妥当性（指標の選定、スコアリング基準、評価者バイアス） | 1.0 | 1.0 | 0.5 |
| R | 前提条件・再現性（環境、バージョン、再現手順、交絡因子、データ汚染） | 2.0 | 2.0 | 1.0 |
| A | 考察・分析（なぜその結果か、論理、限界、COI、一般化範囲） | 1.5 | 1.5 | 1.0 |
| O | 公式情報・出典（公式リンク、第三者結果との比較、日付とバージョン） | 0.5 | 0.5 | 0.5 |
| G | 成果物の生成主体の正確な帰属（LLM 単独かテンプレート・スクリプト併用か、失敗時の代替の明記） | 1.0 | N/A | N/A |
| 合計 | | 10.0 | 9.0 | 6.0 |

減点: サブセクション内で Must 項目（第9節で ★ を付けた項目。原本では太字）の欠落は配点の 50%、Nice 項目（★ なし）の欠落は 20%。複数欠落は合算し、下限 0 点、上限はサブセクション配点。減点額は次の表で引く。軽量化モード（製品レビュー）では Must 欠落の減点率も 20% に緩和する。G は LLM や自動生成ツールの成果物を評価する記事にだけ適用する。冒頭で採用したモード（通常 / 整合性検証 / 軽量化）を明示する。

## 5. 判定ランクと N/A 処理

| 判定 | 素点（110 点満点時） | 比率 | 意味 |
|---|---|---|---|
| S | 99〜110 | 90% 以上 | そのまま公開可 |
| A | 88〜98 | 80% 以上 | 軽微な修正後に公開可 |
| B | 77〜87 | 70% 以上 | 修正推奨 |
| C | 66〜76 | 60% 以上 | 大幅な修正が必要 |
| D | 65 以下 | 59% 以下 | 構成から見直し。0-gate / 4-gate / 9-gate 検出時は点数に関わらず D |

N/A は 3 段階で処理する。(1) 第11項目を含まない記事は項目全体を N/A とし 100 点満点で採点する。(2) 適用外のサブセクションは第11項目の満点をその配点分だけ縮小する（例: G が N/A なら 9.0 点満点）。(3) 適用外の個別チェック項目は減点対象から外す（配点は変えない）。換算は `換算点 = 素点 × 100 / 該当配点合計`（該当配点合計 = 110 − N/A 縮小分）で行い、縮小した満点と換算前後の点数を明記する。

## 6. 記事タイプ別の第11項目の扱い

| 記事タイプ | 第11項目 | 満点 |
|---|---|---|
| 概念解説、トレンド紹介、エッセイ、取材・インタビュー、ハウツー | 項目全体 N/A | 100 |
| 戦略分析・調査（一次計測なし） | 整合性検証モード（引用データの整合性に縮小、G は N/A） | 109 |
| 製品レビュー・購入レポート | 軽量化モード（F のみ Must、G は N/A） | 106（第4節の軽量化列の合計 6.0 + 100） |
| ベンチマーク・速度計測、実証実験 | 全サブ適用、G は N/A | 109 |
| AI/LLM 出力評価 | 全サブ適用 | 110 |

トレンド調査と戦略分析は 4-gate 必須。外部主体への断定がある記事は公式反論・否認の検索（原本の Phase 4b）を別エージェントで実施する。取材記事は第10項目の引用許諾・録音同意・公開前確認を必ず評価する。規制業界の記事は第9項目の業界規制トリガー表を必ず評価し、9-gate を厳格に適用する。

## 7. 0-gate の補助資料（プラットフォーム別制約・絵文字検出コマンド）

### プラットフォーム別の既知制約

| プラットフォーム | 絵文字 | HTML タグ | Frontmatter | 文字数 | その他 |
|---|---|---|---|---|---|
| note | 可 | 限定的（script / iframe は不可） | 不要 | タイトル 100 字 | 見出し階層は浅め、画像 10MB / 枚 |
| Qiita | 可 | 限定的（独自 Markdown 拡張） | 必須（tags 必須） | なし | タグ 5 個上限、コードブロックの言語指定を推奨 |
| Zenn | 可 | 不可（純 Markdown） | 必須（title / topics / published 等） | なし | topics 5 個上限 |
| Medium | 可 | 限定的 | 不要 | なし | メンバーウォール設定 |
| Hatena Blog | 可 | 可 | 不要 | なし | 記法モード（Markdown / はてな記法）の選択が必須 |
| Dev.to | 可 | 限定的 | 必須（cover_image 等） | なし | タグ 4 個上限 |
| WordPress（自己ホスト） | 可 | プラグイン依存 | 不要 | なし | テーマ・プラグイン固有の制約 |
| 企業エンジニアブログ | 社内ガイドライン依存 | サイト依存 | サイト依存 | サイト依存 | 広報・法務レビューの導線、ブランドガイドライン |
| 社内ポータル（CKEditor 系） | 不可（投稿エラー） | サニタイズ強め | 不要 | なし | 装飾絵文字で CMS がエラーになる事例、機密の取扱いが厳格 |

表に無いプラットフォームは、設定欄の記入時に公式ヘルプ・規約・投稿ガイドラインを確認する。

### ゲート通過条件

1. 設定欄の掲載先と既知制約に応じて、上の表か公式ドキュメントで制約を確認する。
2. 制約違反の検出をゼロにする。
3. 検出したら文字・代替記号・装飾タグへ置き換えてから再レビューする（成功の記号は「成功」「OK」、失敗の記号は「失敗」「NG」、警告の記号は「注意」。視覚強調は `strong` や色付き要素で代える）。

### 絵文字検出コマンド

検出対象は Unicode の `U+2600`〜`U+27BF`、`U+1F300`〜`U+1F9FF`、`U+1FA00`〜`U+1FAFF`、`U+2705`、`U+274C`、`U+2714`、`U+2718`。本文・表・SVG の text 要素・figcaption・alt 属性まで対象にする。

```bash
grep -nP '[\x{2600}-\x{27BF}\x{1F300}-\x{1F9FF}\x{1FA00}-\x{1FAFF}\x{2705}\x{274C}\x{2714}\x{2718}]' 対象ファイル
```

PowerShell（.NET 正規表現はサロゲートペアで範囲を書く。1F300 から 1FAFF までを D83C から D83E の上位サロゲートで近似する）:

```powershell
Select-String -Path 対象ファイル -Pattern '[\u2600-\u27BF]|[\uD83C-\uD83E][\uDC00-\uDFFF]'
```

検出がゼロであることがゲート通過の必須条件。1 件でも有れば、プラットフォームの絵文字ポリシーが「制限なし」でない限り 0-gate 違反として判定 D にする。ポリシーが「制限なし」の場合は検出結果を補足コメントに記録して減点しない。

## 8. 9-gate の補助資料（業界規制 NG 表現トリガー表）

設定欄の「業界規制」が該当するときに発動する。NG 表現例に当たり、打消表示・出典・所感扱いへの書き換えのいずれも無ければ 9-gate 違反（判定 D）。

| 業界 | 主要規制 | NG 表現例（断定すると違反リスク） | 推奨表現 |
|---|---|---|---|
| 医療・健康 | 薬機法 | 病気が治る、特定の症状に効く、がんが消える、アンチエイジング効果 | 成分が含まれる、研究では報告されている（論文を出典に） |
| 食品・サプリ | 健康増進法・景表法 | ダイエット効果、免疫力アップ、血圧を下げる（特定保健用食品・機能性表示食品以外で） | 機能性表示食品の届出範囲内のみ、または「個人の感想です」を明記 |
| 化粧品 | 薬機法（効能効果 56 項目） | シワが消える、ニキビが治る、美白（薬用化粧品の承認なしで） | 56 効能の範囲内の表現 |
| 金融・投資 | 金融商品取引法 | 必ず儲かる、年利確実、絶対に損しない、特定銘柄は買い（断定的判断の提供） | 過去の実績は将来を保証しない旨を明記、シミュレーションの前提を明示 |
| 法律・税務 | 弁護士法 72 条・税理士法 | 特定の紛争で勝てる、節税ノウハウの個別助言 | 一般的な情報提供であり個別案件は専門家に相談するよう明記 |
| 不動産 | 宅建業法・景表法 | 絶対に値上がりする、投資用に最適（不実告知） | 過去実績を示し、将来予測は所感扱い |
| 旅行・グルメ | 景表法（優良誤認） | 業界 No.1、最安値、日本一（根拠なし） | 調査機関・出典・調査期間を明記、「自社調べ」を明示 |
| 教育・資格 | 景表法 | 合格率 No.1、絶対合格、100% 内定（根拠なし） | 算出基準・母集団・期間を明記 |
| EU 在住者向け | GDPR | 同意なき個人データ収集の記述、削除を求める権利への違反 | プライバシーポリシーを明記 |
| 米国在住者向け | 各州法（CCPA 等） | 同意なき個人データの第三者提供の記述 | プライバシーポリシーを明記 |

打消表示（「個人の感想です」「効能効果を保証するものではありません」等）で緩和できるのは、打消表示が本文と同じ視認性で置かれている場合だけ。

## 9. 第11項目のチェック ID（F-1 等）の定義

出力の補助表が使う ID の正本。★ は Must、無印は Nice。補助表の行は ID と 1 対 1 で対応させる。

| ID | 確認する内容 |
|---|---|
| F-1 ★ | 比較条件が公平か（同一ハードウェア・データセット・プロンプト・試行回数） |
| F-2 ★ | 特定の対象に有利な条件になっていないか（片方だけ最適化、片方だけウォームアップ済み、片方だけ最新版） |
| F-3 ★ | チェリーピッキングが無いか（失敗例・不利な結果も載せているか） |
| F-4 | 比較対象の選定理由とベースラインが適切か |
| Q-1 ★ | 数値が定量的か（「速い」でなく tok/s・ms・% 等） |
| Q-2 ★ | 単位が明記され統一されているか |
| Q-3 | 測定誤差・ばらつきへの言及（複数回の平均・中央値・標準偏差） |
| Q-4 | サンプル数 n の明記（n=1 での断定をしない） |
| Q-5 | 統計的有意性・信頼区間への言及 |
| C-1 ★ | 評価項目・基準の選定が妥当で、指標と結論が整合しているか |
| C-2 | スコアリング基準を読者が追跡できるか |
| C-3 | 評価者バイアスへの配慮 |
| R-1 ★ | 前提条件（ハードウェア・OS・ソフトウェア版・データセット・パラメータ）の明記 |
| R-2 ★ | バージョンの具体的な特定（リリース番号・コミットハッシュ・ビルド日時） |
| R-3 | 再現手順（コマンド・スクリプト・プロンプト・設定）の公開 |
| R-4 | 複数テスト間の環境差分の明示 |
| R-5 | 環境状態（熱・負荷・電源・ネットワーク）の管理 |
| R-6 | 交絡因子の分離（複数変数が同時に変わっていないか） |
| R-7 | アブレーション（各要素の寄与の分離） |
| R-8 | データ汚染への配慮 |
| A-1 ★ | 結果に対する考察（なぜその結果か）が有るか |
| A-2 ★ | 考察が妥当か（論理の飛躍、相関と因果の混同、サンプル不足での断定が無い） |
| A-3 | 仮説と検証結果の関係の整理 |
| A-4 | ネガティブ結果・棄却した仮説の記載 |
| A-5 | 限界・バイアスの認識 |
| A-6 | 利益相反（COI）の開示（技術評価での評価者の立場。広告・PR 記事の COI は第10項目で見る） |
| A-7 ★ | 結論の一般化範囲が適切か |
| O-1 ★ | 公式情報・一次情報へのリンク |
| O-2 | 第三者ベンチマーク・先行研究との比較 |
| O-3 | 引用情報の日付・バージョンの明記 |
| G-1 ★ | 成果物の生成主体（AI 単独かテンプレート・スクリプト併用か）の正確な記述 |
| G-2 ★ | ファイル名・キャプション・見出しの主張と実装の整合 |
| G-3 | 複数ステージの成否を段階ごとに独立して記録しているか |
| G-4 ★ | AI が失敗し代替手段で補った場合の明記 |
| G-5 | 成果物メタデータと記事の主張の整合 |
| G-6 | 「AI が作った」表現の範囲が適切か |

計算例（通常モード）: Q の Nice 項目 Q-4 が欠落すると 2.0 点 × 20% = 0.4 点減で Q = 1.6 点。R の Must 項目 R-1 が欠落すると 2.0 点 × 50% = 1.0 点減で R = 1.0 点。減点額の早見は次のとおり。

| 2.0 点（F / Q / R） | 1.0 点 | 0.4 点 |
| 1.5 点（A） | 0.75 点 | 0.3 点 |
| 1.0 点（C / G） | 0.5 点 | 0.2 点 |
