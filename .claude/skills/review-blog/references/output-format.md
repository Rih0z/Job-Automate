# 出力フォーマットの要点（原本の自己完結版）

原本 `workflows/content-creation/review-blog.md` の「レビュー結果出力フォーマット」節と同じ構成。原本が有っても無くても、この節構成と `rubric.md` の ID 定義で出力する（細部が食い違えば原本を優先する）。

## 目次

1. 出力の節構成
2. 総合評価の書き方
3. 観点別採点の表
4. 第11項目の補助表
5. 根拠の引用ルール

## 1. 出力の節構成

1. 基本情報: 記事タイトル、レビュー日、レビュワー、設定欄の記入値（A〜D 軸）
2. 総合評価: 素点と該当配点合計、100 点換算点、判定（S/A/B/C/D）、3 ゲートの結果
3. 観点別採点: 11 観点の表
4. 第11項目 サブセクション別採点（技術評価を含む記事のみ）
5. 技術評価の妥当性 詳細チェック（同上）
6. 良かった点（Keep）
7. 改善提案（Problem / Try）
8. 具体的な修正箇所（行番号付き）
9. 補足コメント

## 2. 総合評価の書き方

- 素点: XX 点 / 該当配点合計 ZZ 点（N/A で縮小した場合は ZZ が 110 未満）
- 100 点満点換算: YY 点（`素点 × 100 / 該当配点合計`）
- 判定: S/A/B/C/D のいずれか
- 0-gate: 該当なし（N/A）/ 違反なし / 違反あり（判定 D 固定）
- 4-gate: トリガー語なし（N/A）/ 公式反論検索済みで両論併記済み / 違反あり（判定 D 固定）
- 9-gate: 重大違反なし / 重大違反あり（判定 D 固定）

## 3. 観点別採点の表

列は「番号 / 観点 / 配点 / N/A 縮小後満点 / 得点 / コメント」。11 観点（rubric.md の第3節）を全行並べ、最終行に計（110）を置く。N/A の観点は理由を一言添える。

## 4. 第11項目の補助表

サブセクション別（F / Q / C / R / A / O / G）に、配点、N/A 縮小後、得点、Must 欠落、Nice 欠落、コメントを記入する。詳細チェックは項目 ID（F-1、Q-1 など。ID と内容と Must の印は `rubric.md` 第9節で定義）ごとに 1 行とし、評価記号を付ける。

| 記号 | 意味 |
|---|---|
| 丸 | 十分に満たしている |
| 三角 | 部分的に満たすが、重要な要素が 1〜2 点欠落 |
| バツ | 満たしていない、記載が無い、誤りがある |
| N/A | 記事の性質上、適用対象外 |

Must 項目の行には星印を付ける。

## 5. 根拠の引用ルール

減点、ゲート判定、改善提案の各指摘に、記事内の該当箇所（見出し名または行番号と短い引用）を添える。引用できない指摘は出さない。レビュワーは対象ファイルを編集せず、修正は提案として書く。
